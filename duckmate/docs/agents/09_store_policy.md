## 다음 에이전트에게 넘기는 결정사항

**Phase 1~3 웹 코드에 지금부터 반영해야 Phase 4(앱 래핑·IAP)에서 재작업이 없는 항목.** 번호 앞 `[P1]`/`[P3]`는 반영 Phase.

1. `[P1]` **로그인은 휴대폰 OTP 단일 유지**(PRD §0-19). Apple 4.8은 "제3자/소셜 로그인"을 쓸 때만 Sign in with Apple(또는 동등 옵션) 의무이며, 자사 계정 시스템만 쓰면 **면제**. 따라서 Phase 4에 카카오/구글 로그인을 추가하려면 **Sign in with Apple을 반드시 같이** 넣어야 한다 → 소셜 로그인 추가는 Phase 4 이후 별도 결정, D2는 `auth_provider` 컬럼(enum: `phone`/`apple`/`kakao`/`google`)만 미리 둔다.
2. `[P1]` **계정 삭제는 앱 내 경로 필수**(Apple 5.1.1(v), Google 계정 삭제 정책). PRD F-039 탈퇴(확인 1회 + 7일 유예)는 허용되나, 화면에 "7일 후 완전히 삭제되며 유예 중 재로그인하면 취소됩니다"를 **명시**해야 한다. 라우트는 `/settings/account`에서 **2탭 이내**, 이름은 "계정 삭제"(휴면·비활성화와 구분되는 별도 버튼).
3. `[P1]` **웹 계정 삭제 URL 별도 제공**: Google Data Safety 양식이 앱 외 웹 URL을 요구 → `/account/delete`(로그인 후 동일 플로우) + 미로그인 시 안내 페이지를 `(public)` 그룹에 둔다. company 사이트 푸터에도 링크.
4. `[P1]` **개인정보처리방침 URL 고정**: `{{DOMAIN}}/legal/privacy`는 스토어 메타데이터 필드에 들어가므로 Phase 1부터 경로 불변. Phase 4 전에 다음 항목 추가: 푸시 토큰(FCM/APNs), 광고 식별자(AdMob 도입 시), 연락처 해시(F-085 도입 시), 앱 스토어 결제 정보(Apple/Google이 결제 정보를 처리한다는 고지).
5. `[P1]` **모든 결제 UI를 `PaymentProvider` 인터페이스 뒤에**: `packages/db/src/payments/provider.ts`에 `{ listSkus(), purchase(sku), restore(), manageSubscriptionUrl(), refundPath() }`를 정의하고 Phase 3 `TossProvider`, Phase 4 `StoreProvider(RevenueCat)`가 구현. E4의 상점 시트·구독 관리 화면은 provider가 주는 데이터(가격 문자열·버튼 라벨·관리 링크)만 렌더하고 Toss 고유 UI(카드 등록 등)는 `TossProvider` 내부 컴포넌트로 격리.
6. `[P3]` **`subscriptions.provider` enum = `toss` | `apple` | `google`**, `payments.provider`도 동일. `provider_sub_id`는 RevenueCat `original_transaction_id`/`purchase_token`을 그대로 저장. D1이 Phase 3 마이그레이션 파일에 enum을 확정하고 Phase 4는 값만 추가 없이 사용.
7. `[P3]` **권한 판정은 `get_effective_tier(user_id)` 서버 단일 함수 유지**(A4). provider가 무엇이든 활성 `subscriptions` 행 → tier. 클라이언트/RevenueCat SDK의 entitlement 값을 **UI 캐시로만** 쓰고 보안 경계로 쓰지 않는다.
8. `[P3]` **가격 표기는 `skus.price_krw`가 아니라 provider가 준 표시 문자열**(`display_price`)을 렌더. 스토어 가격은 스토어가 정한 가격 포인트라 웹과 다를 수 있고(₩9,900 → 스토어 티어 매핑 `(확인 필요)`), 앱 빌드가 웹 가격을 렌더하면 3.1.1 위반·오표시. `skus`에 `apple_product_id`·`google_product_id` 컬럼을 Phase 3에 미리 추가.
9. `[P3]` **런타임 플랫폼 플래그 1곳**: `packages/db/src/platform.ts`의 `isNativeApp()`(Capacitor `isNativePlatform()` 래핑, 웹은 false). 결제·웹 유도 문구·외부 링크 분기는 전부 이 함수만 참조. 빌드타임 상수(`NEXT_PUBLIC_BUILD_TARGET=web|ios|android`)도 병행해 정적 export에서 트리쉐이킹.
10. `[P3]` **"웹에서 더 싸게" 류 카피 금지 컴포넌트화**: 웹 결제로 유도하는 모든 문구·링크·버튼은 `<WebOnly>` 래퍼 안에만 두고 `isNativeApp()`이면 렌더 0. 앱 빌드 grep 가드(`scripts/check-store-copy.mjs`)로 `웹에서`·`홈페이지에서 결제`·`toss` 단어를 앱 번들에서 탐지.
11. `[P3]` **결제 화면의 사업자 정보·전자상거래법 고지·Toss 환불 버튼**은 `TossProvider` 전용 슬롯. 앱 빌드에서는 "환불·구독 관리는 App Store/Google Play에서" 링크로 교체(§4.5).
12. `[P1]` **`profiles`에 `platform_first_seen`·`push_tokens` 테이블 분리**: Web Push `push_subscriptions`와 별개로 `device_tokens(user_id, platform, token, created_at, last_sent_at)`를 Phase 1 스키마 파일에 두면 Phase 4 FCM/APNs 전환 시 스키마 변경 0.
13. `[P1]` **푸시 슬롯 B(온보딩 미완료 리마인드·추천 미완료)는 "마케팅성"으로 분류**: Apple 4.5.4는 사용자 동의 없는 프로모션 푸시 금지, Google도 동일 → 설정 화면에 슬롯별 on/off(PRD §4.8 이미 있음)를 **가입 직후 기본 on이 아닌 명시 동의**로 바꾸고 동의 시각 저장(`notification_consents`).
14. `[P1]` **위치 권한 미사용 확정**: GPS·IP 위치 미수집(PRD §0-22). Phase 4 네이티브 프로젝트에 위치 권한 문자열·`NSLocationWhenInUseUsageDescription` 자체를 넣지 않는다. `region_code`는 사용자 입력이므로 스토어 양식에 "위치" 아닌 "개인정보(주소/지역)"로 신고 `(확인 필요)`.
15. `[P1]` **사진 업로드는 OS 포토 피커만**(Apple 5.1.1(iii), Google Photo/Video 권한 정책): 전체 사진 라이브러리 권한 요청 금지. 웹 `<input type=file accept=image/*>`는 Capacitor에서 시스템 피커로 동작하므로 그대로 유지. 카메라는 "지금 찍기"를 넣을 때만 권한 요청 + 사유 문자열.
16. `[P1]` **연락처 접근 코드 금지(F-085 전까지)**: Phase 4 "아는 사람 차단"은 민감 권한(Contacts)이며 스토어 양식·Prominent Disclosure·옵트인이 필요. 도입 전까지 어떤 코드도 연락처 API를 참조하지 않는다.
17. `[P1]` **연령 등급 메타 = Apple 18+ / Google IARC 18+ + "선언된 미성년자 차단"**: Apple은 2025~26 개편으로 17+가 **18+**로 바뀌었고(개편 설문 마감 2026-01-31), Google은 2026-01-28부터 데이팅 앱에 Play Console "Restrict Declared Minors" 설정 의무. 브리프·PRD의 "17+/19+" 표기를 **"18+(스토어) / 만 19세(서비스 약관)"**로 정정. 앱 스토어 설명·스크린샷에 성적 암시 0.
18. `[P1]` **개발자 계정은 법인(조직) 명의**: Apple 5.1.1(ix) "민감 정보를 요구하는 앱은 개인 개발자가 아닌 법인이 제출". 본인인증·결제를 다루므로 소유자는 Phase 3 전에 D-U-N-S 번호·조직 계정(Apple Developer Program 조직, Google Play 조직 계정) 준비. `{{COMPANY_NAME}}` 확정과 같은 게이트.
19. `[P1]` **심사관용 계정 경로 설계(D2)**: `IDENTITY_MOCK_ALLOWLIST`와 별개로 `review_accounts` 개념 — Supabase Auth의 **테스트 OTP 번호**(고정 코드) 2개 + 서버 시드로 `verify_level=3`·`is_review=true`. `is_review=true`는 추천 풀에서 서로만 매칭되도록 리전 `REVIEW` 격리, 실사용자에게 비노출, 90일 후 자동 비활성(§8).
20. `[P1]` **UGC 4대 요건의 위치 고정**: 필터링(D4 룰), 신고(1탭, 채팅 헤더·프로필), 차단(신고 완료 화면 + 프로필 더보기), **연락처 게시**(Apple 1.2: 이메일/문의 경로가 앱 안에서 1탭) → 설정 화면에 "문의하기" 항목(`inquiries` 폼 + 공개 이메일 `{{SUPPORT_EMAIL}}` 플레이스홀더). 스크린샷으로 심사 노트에 첨부.
21. `[P1]` **탈퇴·삭제 시 보존 항목 고지**: 5.1.1(v)·Google 정책 모두 "법적 보존 예외는 사용자에게 알리면 허용". 계정 삭제 화면에 A5 §11.1 보존 항목(결제 5년·CI 해시 1년·신고 증거)을 요약 노출.
22. `[P1]` **앱 내 개인정보 방침·약관 링크는 로그인 전 화면(S1)에서도 도달** 가능해야 함(Apple 5.1.1(i) "쉽게 접근"). 온보딩 S1 하단 링크 + 설정.
23. `[P3]` **구독 정보 고지 컴포넌트를 provider 중립으로**: "매월 {일} ₩{금액} 자동 결제 · 언제든 해지"(A4)는 유지하되 금액·주기 값은 provider에서. 앱은 추가로 Apple Schedule 2 필수 문구(구독 기간·가격·자동 갱신·해지 방법·약관/개인정보 링크)를 같은 컴포넌트에 표시.
24. `[P3]` **한 유저 한 활성 구독 규칙(DB 제약)**: `subscriptions`에 `status='active'` 부분 유니크 인덱스 `(user_id) WHERE status IN ('active','past_due')`. provider가 달라도 2행 불가 → Phase 4 중복 구독 방지의 근간(§4.2).
25. `[P1]` **앱 배포 지역 = 한국 스토어프런트만(Phase 4 초기)**: Apple 3.1.1(a) 외부 결제 조항은 스토어프런트별로 다르므로 한국 외 배포는 별도 검토. `apps/web` 카피·법적 페이지는 한국어 단일.

### 2.3 5.1.1 데이터 수집·개인정보·계정 삭제
- (i) 개인정보처리방침 링크: App Store Connect 필드 + 앱 내 로그인 전 도달. 제3자(포트원/PASS·Supabase·Vercel·RevenueCat·FCM/APNs·AdMob)를 방침에 열거.
- (ii)/(iv) 권한: 사진 피커·카메라·알림·(F-085) 연락처 각각 목적 문자열, 거부 시 대안 제공(사진 없이 진행 가능 — 이미 PRD S6).
- (iii) 데이터 최소화: 본인인증 결과 중 **이름 미저장**(PRD §5.4) 유지 — 심사 노트에 기재하면 유리.

### 2.4 3.1.1 IAP 의무 범위와 외부 결제
- **구독(플러스/프로)·소모성(슈퍼라이크·부스트·되돌리기·카드 리필) 전부 IAP 의무**. 자체 언락 수단(웹 결제 코드·쿠폰 등)으로 앱 내 기능을 여는 것은 금지.
- IAP로 산 소모성은 **만료 불가** ("credits purchased via IAP may not expire") → A4의 **부스트 90일 만료·카드 리필 당일 소멸은 IAP 판매분에 적용 불가**. 대응: 앱 SKU에서는 `boost_1h` 만료 없음, `card_refill_3`은 IAP 미판매(웹 전용) 또는 "당일 사용 가능 횟수 추가권(만료 없음)"으로 재정의 `(D6·A4 재확인)`.
- **복원(Restore)** 버튼 필수(비소모성/구독). 상점 시트 하단 "구매 복원".
- **3.1.3(b) 멀티플랫폼**: 웹(Toss)에서 산 구독을 앱에서 쓰게 하는 것은 **허용**되며 조건은 "같은 항목이 앱 내 IAP로도 제공될 것". 단 앱 안에서 웹 결제를 **권유**하는 것은 금지(§5).
- **3.1.1(a) 외부 결제 링크**: 미국 스토어프런트만 제한 없음. 그 외 지역은 Apple 자격(entitlement)이 필요. **한국**: 2022년부터 "StoreKit External Purchase Entitlement(한국)"로 **앱 내 제3자 PG(KCP·이니시스·토스·NICE 등 사전 승인 PG) 결제**를 허용하되 수수료 **26%** + 월별 매출 보고 + 별도 바이너리 제출 조건. 방미통위는 이 구조가 인앱결제 강제금지법(전기통신사업법 §50①9) 위반이라며 2023-10 과징금(애플 205억·구글 475억)을 예고했으나 2026-09 현재 재심의 중, 부과 미확정 `(확인 필요)`. → **덕메이트 Phase 4 초기는 표준 IAP만** 사용하고 한국 외부 결제 자격은 매출 규모가 수수료 차이를 정당화할 때 재검토(§4.6).
- 소액 사업자 프로그램(Small Business Program, 연 $1M 이하 15%) 신청 — 조직 계정 확보 후 즉시.

- 원칙: 앱 내 디지털 상품·구독은 **Google Play 결제 시스템** 사용. 한국은 인앱결제 강제 금지법(2021 전기통신사업법 개정) 이후 **제3자 결제(User Choice/대체 결제)** 선택지가 2022년부터 존재 — 대체 결제 시 서비스 수수료 4%p 감면(30%→26%, 구독 15%→11%)이라 PG 수수료를 더하면 실익이 거의 없었다.
- **2026 변경(구글 발표, 한국 시행 2026-12 예정)** `(확인 필요: 확정 요율·시행일)`: 결제 방식과 무관하게 **연 첫 $1M(약 11~15억) 구간 10%**, 초과분 최대 20%, Play 결제 사용 시 **결제 수수료 5%** 별도, **대체 결제·외부 웹 링크 거래에는 추가 수수료 없음**, 개발자 자체 결제 선택 화면 허용(UX 가이드 준수). 방미통위 과징금 심의는 별개로 진행 중.
- **덕메이트 판단**: Phase 4 초기(예상 매출 < $1M)는 Google Play 결제 단일(10%+5%). 매출·환불 운영 부담(대체 결제 시 환불·영수증·세금 전부 자체) 대비 절감이 유의미해지면 Toss를 **앱 내 대체 결제 옵션**으로 병행(§4.6).

## 4. IAP 전환 설계 (Phase 4, D6·E4)

### 4.1 구성
- RevenueCat: iOS/Android SDK + **웹훅 → Supabase Edge Function `store_webhook`**이 `subscriptions`·`payments`·`item_ledger`를 갱신. 클라이언트가 직접 `subscriptions`를 쓰지 않음(RLS로 차단, service role만).
- `subscriptions.provider ∈ {toss, apple, google}`, `provider_sub_id` = RevenueCat `original_transaction_id`(Apple)/`purchase_token`(Google). RevenueCat `app_user_id` = Supabase `user_id`(익명 ID 사용 금지 → 기기 간·웹 간 동일 유저 식별).
- 소모성: 스토어 구매 이벤트(`NON_RENEWING_PURCHASE`/consumable) → `item_ledger` `purchase:{payment_id}` 적립. **IAP 구매분은 만료 없음**(§2.4).

### 4.2 병존 규칙 (Toss 웹 구독 ↔ 스토어 구독)
| 상황 | 규칙 |
|---|---|
| 활성 Toss 구독 유저가 앱 상점 진입 | 구독 카드에 "현재 구독 이용 중 · {provider 표시명}에서 관리" 만 표시, **구매 버튼 비활성**. 웹 링크·가격 비교 문구 없음(3.1.3(b) 허용 범위 = 접근만) |
| 활성 스토어 구독 유저가 웹 상점 진입 | "App Store/Google Play 구독 이용 중 · 스토어에서 관리" + 딥링크 |
| 두 경로 동시 활성 시도(레이스) | DB 부분 유니크 인덱스(결정사항 24)로 두 번째 insert 실패 → 웹훅 핸들러는 실패 시 RevenueCat/Toss 측 **자동 환불 요청 + 운영 알림**(`duplicate_charge` 사유, 전액) |
| Toss `canceled`(기간 말 종료) 상태에서 앱 구독 | 허용하되 시작일 = 기존 `current_period_end` 이후로 안내(중복 기간 방지). 즉시 시작을 원하면 웹에서 먼저 환불 |
| 티어 변경(플러스↔프로) | 같은 provider 안에서만(스토어 구독 그룹/Base plan). 교차 provider 업그레이드는 "기존 구독 종료 후" 안내 |
| 권한 판정 | `get_effective_tier`는 provider 무관 `status IN (active, past_due)` 행 1개를 읽는다. `past_due`(스토어 결제 재시도 유예)는 스토어 grace period 설정과 동일 기간 |

### 4.3 웹→앱 전환 유저
- 로그인만 하면 서버 tier가 그대로 적용(추가 조치 0). 상점에서는 §4.2 1행.
- Toss 구독 해지 후 앱 재구독 시 A4 "만료 D-3 알림 1회" 외 유도 없음.
- 웹 구매 소모성 잔액은 ledger이므로 앱에서 그대로 사용 가능(3.1.3(b) "다른 플랫폼에서 획득한 소모성 접근 허용").

### 4.4 가격 표기
- 앱 가격은 스토어 가격 포인트에서 선택: 웹 ₩9,900/₩19,900이 그대로 있는지 `(확인 필요: Apple KRW 가격 포인트 목록)`. 수수료 반영 상향(A4 §10 "₩12,000/₩24,000")은 **허용**되나 앱 안에서 웹 가격과 비교·언급 금지. 웹에서는 "앱 가격은 스토어 수수료로 다를 수 있음" 고지 가능(E4).
- 표시는 provider `display_price`(현지화 문자열)만. 일 환산 표기(A4 §5-9)는 앱에서도 보조로만.
- 세금: 스토어 가격은 VAT 포함가. 웹 Toss 가격도 VAT 포함 표기로 통일(전자상거래법).

### 4.5 환불·구독 관리(앱)
- IAP 환불은 스토어 절차(Apple: reportaproblem.apple.com / Google: Play 결제 내역 또는 개발자 승인). `compute_refund`(A4 §6)는 **Toss provider에만** 실행. 앱 결제 내역 화면의 "환불 요청" 버튼은 provider별 분기: Toss → 기존 플로우, apple/google → 스토어 안내 딥링크. A4 §5-14("이메일로만 접수 금지")는 스토어 경로 안내로 충족.
- 스토어 환불 웹훅(`REFUND`/`CANCELLATION`) 수신 시 `subscriptions.status='refunded'` + ledger `refund_reversal` — Toss와 동일 함수 재사용.
- 해지: 앱은 스토어 딥링크(2탭 규칙 유지). 앱 내에서 "해지되었습니다" 확인은 웹훅 반영 후 표시.

### 4.6 한국 외부 결제 옵션(보류 기준)
| 조건 | 결정 |
|---|---|
| 연 스토어 매출 < $1M | 표준 IAP만 |
| Google 2026 신요율 시행 후 대체 결제 추가 수수료 0 확인 | Android에 Toss를 **선택 화면**(Google UX 가이드) 병행 검토 — provider enum은 그대로 `toss`, `platform` 컬럼으로 구분 |
| Apple 한국 자격(26% + 월 보고 + 별도 바이너리) | 실익 없음 → 보류. 방미통위 제재 결과로 조건이 바뀌면 재검토 `(확인 필요)` |

## 6. Capacitor 래핑 심사 리스크 (4.2 최소 기능)

**리스크**: "Safari와 다르지 않은 경험"으로 4.2 반려. 데이팅 앱은 4.3(b)까지 겹쳐 반려 확률이 높다. 심사관은 웹뷰 안이 아니라 **웹뷰 밖에 무엇이 있는지** 본다.

네이티브 기능 최소 목록(Phase 4 Must):
1. **네이티브 푸시**(FCM/APNs, F-083) — 심사 노트에 "매칭·메시지 알림"으로 시연.
2. **딥링크/유니버설 링크**: `duckmate://match/{id}`, `https://{{DOMAIN}}/chat/{id}` → 앱 열림. 푸시 탭 → 해당 방.
3. **햅틱**: 좋아요·매칭 성사·카드 뒤집기(`@capacitor/haptics`), `prefers-reduced-motion` 존중.
4. **카메라/피커**: 시스템 사진 피커 + (선택) 즉석 촬영.
5. **오프라인/네트워크 처리**: 오프라인 배너, 채팅 전송 큐(재시도), 스플래시 후 캐시된 마지막 화면. 빈 흰 화면·브라우저 에러 페이지 0.
6. **네이티브 내비게이션 감각**: 안드로이드 하드웨어 뒤로가기 처리, iOS 스와이프 백 대응, 상태바·세이프 에어리어, 키보드 회피, pull-to-refresh 비활성(웹 느낌 제거).
7. **앱 아이콘·스플래시·런치 스크린** 커스텀, 외부 링크는 인앱 브라우저(SFSafariViewController/Custom Tabs)로.
8. **네이티브 공유 시트**(취미 이벤트·초대 링크), 클립보드.
9. **생체 인증 잠금**(선택, `@capacitor-community/biometric`)은 데이팅 앱에서 4.2 방어에 효과적 — Should.
10. **로컬 알림**(07:00 새 추천 예약) — 푸시 미허용 유저 대체, Could.

추가 대응: 앱 번들에 정적 export 포함(원격 URL 로딩 웹뷰 금지 — Apple은 원격 로드를 "웹 클리핑"으로 봄), 로딩 인디케이터 네이티브, 웹 전용 요소(쿠키 배너·"앱 설치" 배너·브라우저 주소 표시) 제거.
