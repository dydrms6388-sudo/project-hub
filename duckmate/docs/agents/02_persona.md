# 02 — 페르소나 / JTBD (A2)

> 근거: `00_brief.md`. 수치(이탈률·비율)는 **가설**이며, Phase 1 배포 후 실측(퍼널 이벤트)으로 교체한다.
> 취미 슬러그·퀴즈 카테고리 명명은 D1 스키마(`hobbies.slug`, `quiz_questions.category`)를 따른다.

## 다음 에이전트에게 넘기는 결정사항

- **P1 기본 모드 = '취미 친구'**. 가입 직후 `profiles.mode='friend'` 고정, 데이팅 모드는 `verify_level>=2`(본인인증 완료) 이후 프로필 설정에서 **명시적 옵트인**. 모드 선택 화면을 온보딩 안에 넣지 않는다(4개 페르소나 중 3개가 온보딩 시점엔 데이팅을 원하지 않음).
- **덕질 카드가 사진보다 먼저**. 프로필 뷰·추천 카드·매칭 알림 모두 첫 화면은 덕질 카드(Top3 + 최애 + 요즘 빠진 것), 사진은 카드 뒤/스크롤 아래. 사진 없이도 친구 모드 노출 허용(`photos.is_primary` 없으면 아바타 대체). 데이팅 모드만 사진 1장 필수.
- **온보딩 단계 순서 확정**: 연령확인 → 휴대폰 → 취미 5개 → 퀴즈 10문항 → 덕질 카드 → 사진. 단, **퀴즈·사진은 "나중에"로 스킵 가능**하며 스킵 시 매칭 점수에서 해당 가중치(0.35 / 0)는 중립값 처리. 취미 5개·덕질 카드는 스킵 불가.
- **취미 5개 선택 화면은 검색 + 카테고리 칩 + "최근 인기" 3열**. 덕질 몰입형은 `fav_note`(최애/작품명 자유 입력)를 취미 선택 단계에서 바로 쓰고 싶어함 → 취미 칩 탭 시 인라인 fav_note 입력(선택) 제공.
- **`profile_hobbies.intensity`는 5단계 라벨 필수**: 1 "관심 있음" / 2 "가끔" / 3 "주 1회" / 4 "거의 매일" / 5 "이게 인생". 입문형과 몰입형을 같은 태그 안에서 구분하는 유일한 축이므로 매칭 점수(D3)에서 자카드 계산 시 intensity 차이 ≥3 이면 페널티 권고.
- **첫 대화 제안 카드는 3장, 유형 고정**: ① 온라인에서 지금 할 수 있는 것(같이 보기/게임 한 판/플리 공유) ② 오프라인 활동(장소·시간대 포함, 공개 장소만) ③ 취미 질문(최애 관련 오픈 질문). 온라인 선호형은 ①, 오프모임 선호형은 ②를 우선 노출하도록 `availability`·`intensity` 기반 정렬.
- **안전 UI 기본값**: 매칭 후 첫 7일 또는 첫 20메시지까지 `messages.masked_body`로 전화번호·카톡ID·계좌 자동 마스킹, 이미지 전송은 상호 인증(`verify_level>=2`) 이후. 신고 버튼은 채팅 헤더 1탭. 차단 시 상대에게 알림 없음.
- **위치는 `region_code`(시/군/구) 이상 세분화 금지**. 오프모임 선호형도 "동네" 수준이면 충분. 동선·실시간 위치 표시 기능은 로드맵에서 제외.
- **다크패턴 금지 목록 추가분**(A4/E4 반영): 가짜 "누군가 당신을 좋아해요" 블러 알림 금지, 스트릭 끊김 협박 카피 금지, 사진 미등록 시 "매칭 확률 90% 감소" 같은 미검증 수치 카피 금지, 모드 전환 시 프로필 자동 공개 금지, 탈퇴 시 재확인 1회 초과 금지.
- **결제 트리거 우선순위**(D6): ① 나를 좋아한 사람 공개(몰입형·데이팅 모드) ② 일일 추천 확장(오프모임형: 지역 풀 부족 해소) ③ 되돌리기(입문형) ④ 이벤트 우선 참가(오프모임형). 소모성 부스트는 페르소나 4개 모두에서 트리거 약함 → P3 초기엔 구독 2종만.
- **퀴즈 10문항은 취미 카테고리와 무관한 "생활 궁합"만** (예: 약속 전 연락 빈도, 처음 만날 때 선호 규모, 소비 성향, 밤/아침형). 취미 지식 퀴즈는 Phase 2 게임으로 분리.
- **'나도 초보' 배지**: 입문형을 위해 intensity 1~2 취미가 Top3에 있으면 자동 "입문 환영" 태그를 덕질 카드에 표시. 몰입형이 입문형을 필터링할 수 있게 추천 설정에 "비슷한 몰입도 우선" 토글.
- **탈퇴/휴면 = 1탭 접근**. 설정 → 계정 → 휴면(paused)/탈퇴. `status='paused'` 시 추천·노출·푸시 전부 중단, 매칭 이력은 보존.
- **KPI 계측 이벤트명 확정 요청**(E그룹): `onb_age_pass`, `onb_phone_pass`, `onb_hobby_done`, `onb_quiz_done|skip`, `onb_card_done`, `onb_photo_done|skip`, `first_like`, `first_match`, `first_msg_sent`, `first_msg_replied`, `meet_proposed`. 퍼널 가설 검증용.

## 2. JTBD (When… I want to… so I can…)

**P1 덕질 몰입형**
1. 컴백/콘서트 시즌이 시작될 때, 같은 팬덤 사람을 안전하게 찾고 싶다, 동행·팬싸 정보를 사기 걱정 없이 나눌 수 있도록.
2. 데이팅 앱 자기소개를 쓸 때, 최애와 굿즈 지출을 숨기지 않고 그대로 보여주고 싶다, "이해해주는 사람"만 만나도록.
3. 매칭 상대와 첫 대화를 시작할 때, 상대가 내 최애를 이미 알고 있길 원한다, "그게 누구예요?"부터 설명하지 않도록.

**P2 취미 입문형**
1. 새 취미를 시작했는데 혼자 가기 어색할 때, 나처럼 초보인 동행을 찾고 싶다, 첫 방문 문턱을 넘을 수 있도록.
2. 자기소개를 쓸 때, 취미가 얕아도 채워지는 프로필을 원한다, 매칭 대상에서 배제되지 않도록.
3. 매칭 후 대화가 막힐 때, 앱이 대화 소재를 제안해주길 원한다, "할 말 없음"으로 관계가 끊기지 않도록.

**P3 오프모임 선호형**
1. 주말 러닝/보드게임 일정을 짤 때, 같은 지역·같은 시간대 사람을 찾고 싶다, 채팅 없이 바로 같이 활동해볼 수 있도록.
2. 매칭 후 약속을 잡을 때, 상대 인증 여부와 노쇼 이력을 알고 싶다, 시간 낭비와 안전 위험을 줄일 수 있도록.
3. 추천이 바닥났을 때, 같은 지역 풀을 넓히고 싶다, 이번 주말 안에 실제 만남을 만들 수 있도록.

**P4 온라인 대화 선호형**
1. 밤에 같이 게임할 사람이 필요할 때, 같은 시간대에 접속하는 같은 게임 유저를 만나고 싶다, 오늘 밤 바로 같이 놀 수 있도록.
2. 프로필을 만들 때, 얼굴 사진 없이도 취향으로 나를 표현하고 싶다, 외모 평가 없이 대화로 판단받도록.
3. 대화가 깊어졌을 때, 오프라인 만남은 내 속도로 결정하고 싶다, 압박 없이 관계를 이어갈 수 있도록.

## 4. '취미 친구' 모드 vs '데이팅' 모드

| 페르소나 | 첫 선택 | 이유 | 모드 전환 트리거 | 전환 시 우려 |
|---|---|---|---|---|
| P1 몰입형 | **취미 친구** (초기), 1~2주 후 데이팅 병행 | 팬덤 동행이 1차 목적. 데이팅은 "같은 팬덤이면 좋겠다"는 잠재 욕구 | 친구 모드에서 같은 팬덤 인증 회원과 매칭·대화가 3회 이상 성공 → "데이팅 모드에서도 같은 취미 사람만 만나요" 안내 시 전환 | 팬덤 계정과 데이팅 활동이 연결되어 소문나는 것 → 모드별 노출 대상 완전 분리 필요 |
| P2 입문형 | **취미 친구** | 데이팅 앱 실패 경험, 자신감 부족. "친구부터" | 친구 모드에서 첫 오프라인 동행 1회 성공 + 상대가 데이팅 모드 회원임을 알게 됨 → 전환 | 데이팅 모드로 바꾸면 사진 필수·프로필 압박 → 사진 1장으로 충분함을 명시 |
| P3 오프모임형 | **데이팅** (인증 즉시) | 목적이 명확. "친구 모드는 소모임 앱과 차이 없음" | 반대 방향: 데이팅 모드에서 같은 지역 풀 고갈 시 친구 모드로 **병행**해 러닝 크루 확장 | 데이팅 모드 회원이 친구 모드 사람에게 데이팅 의도로 접근하는 것을 시스템이 막아야 함(양쪽 모드 일치할 때만 매칭) |
| P4 온라인형 | **취미 친구** (장기) | 만남 압박 회피. 온라인 관계 자체가 목적 | 특정 1인과 온라인 대화 2~4주 지속 + 상대가 인증 회원 → 본인이 스스로 전환. **시스템이 전환을 권유하면 역효과** | 전환 즉시 사진 공개·위치 노출될까 봐 → 전환 시 공개 범위 미리보기 제공 |

**설계 원칙 (전 페르소나 공통)**
- 매칭은 **양쪽 모드가 같을 때만** 성립. 친구 모드 ↔ 데이팅 모드 교차 추천 금지(`profiles.mode` 필터를 추천 쿼리 최상위 조건으로).
- 모드 전환은 언제든 가능하되 **전환 시 프로필 공개 범위 미리보기** 화면 1장 필수. 자동 공개·자동 사진 노출 금지.
- 모드 전환 권유 푸시는 P1·P2 조건 충족 시에만 1회, P4에게는 보내지 않음(`availability`가 night 위주 + 만남 제안 0회면 권유 억제).
- 친구 모드 채팅에서 상대가 데이팅 의도를 강하게 드러내면 "데이팅 모드로 함께 전환할까요?" 양쪽 동의형 카드로 처리(일방 전환 불가).

### 다크패턴/기능 금지 목록 (A4·E4·D6 반영 요청)

**금지 — 알림/카피**
1. 가짜·과장 좋아요 알림("누군가 당신을 좋아해요" 실제 like 없이 발송)
2. 스트릭 끊김 협박("지금 안 하면 7일 기록이 사라져요")
3. 미검증 수치 카피("사진 등록 시 매칭 3배")
4. 자책 유도("매칭이 안 되는 이유는 프로필 때문")
5. 만남 압박("아직 안 만났어요?", "만나야 진짜예요")
6. 희소성 압박 결제 카피("지금 안 사면 사라져요")
7. 푸시 일 2건 초과, 심야(00~08시) 마케팅 푸시

**금지 — 기능/UX**
8. 얼굴 사진 필수(친구 모드) — 데이팅 모드만 1장 필수, 검수 통과 기준은 "실제 인물"이지 "얼굴 점수" 아님
9. 외모 점수·매력도 랭킹·"인기 회원" 라벨
10. 무제한 스와이프(일일 추천 상한 유지)
11. 실시간 위치·반경 노출, `region_code` 이하 세분화
12. 친구/데이팅 모드 교차 추천·교차 DM
13. 미인증(`verify_level<2`) 간 DM, 미인증에게 이미지·연락처 전송 허용
14. 모드 전환·구독 시 프로필/사진 자동 공개 범위 확대
15. SNS 계정 연동 강제, 연락처 동기화 강제
16. 채팅에서 계좌번호·전화번호·외부 메신저 ID 자동 마스킹 해제 옵션을 첫 7일 내 제공
17. 탈퇴 2단계 이상 확인, 탈퇴 시 "할인 제안" 팝업, 휴면 기능 숨김
18. 자동갱신 고지 축소, 해지 3뎁스 이상, 무료체험 종료 미고지
19. 신고자에게 처리 결과 미통보(24h SLA 내 1차 회신 필수), 차단 사실을 피차단자에게 알림
20. 매칭 상대 프로필 스크린샷 방지 부재 — 최소한 채팅 이미지 워터마크(닉네임)와 스크린샷 감지 시 안내(기술 한계 명시)

**권장 — 필수 장치 (금지의 반대편)**
- 노쇼 신고 사유 코드(`reports.reason_code='no_show'`) + 2회 누적 시 데이팅 모드 일시 제한(`sanctions.level`)
- 상대 카드에 인증 마크(verify_level) 상시 표시
- 채팅 첫 화면에 "안전 수칙 3줄"(공개 장소·연락처 공유 주의·신고 1탭) 1회 노출, 재노출 없음
- "매칭 0건" 상태에 대체 행동 제공(이벤트 둘러보기·덕질 카드 다듬기 제안), 자책 카피 금지

## 부록: 페르소나 간 충돌과 조정

| 충돌 | 조정안 |
|---|---|
| P1(몰입도 5)이 P2(몰입도 2)와 매칭되면 P1은 실망, P2는 위축 | `intensity` 차이 ≥3 페널티 + "비슷한 몰입도 우선" 토글 + P2 카드에 "입문 환영" 배지로 기대치 사전 정렬 |
| P3는 빨리 만나고 싶고 P4는 만남을 미룸 | 첫 대화 제안 카드 유형을 `availability`·과거 만남 제안 이력으로 정렬. 양쪽 활동 시간대 겹침(0.15 가중)이 낮으면 애초에 추천 점수가 낮아지므로 자연 분리 |
| P3의 지역 풀 부족 vs P4의 지역 무관 | 친구 모드에서 P4는 `region_code` 필터 완화 옵션("온라인 위주라 지역 상관없어요") 제공. 데이팅 모드는 지역 필터 유지 |
| 사진 스킵 허용(P2·P4) vs 인증·안전(P3) | 사진 스킵은 친구 모드에서만. 인증 마크(휴대폰=1, 본인인증=2)는 사진과 별개로 표시하여 P3가 판단 가능 |

## 부록 2: Phase 1 E2E 검증 시나리오 (페르소나 기준 — E그룹 Playwright 참고)

| 페르소나 | 시나리오 (가입→인증→매칭→채팅) | 통과 기준 |
|---|---|---|
| P1 서윤 | 취미 검색 "아이돌" → 칩 선택 후 fav_note "○○(그룹명)" 입력 → 퀴즈 10문항 완료 → 덕질 카드에 최애 표시 → 추천 5장 중 fav_note 일치자 존재 → 좋아요 → 매칭 → 첫 대화 카드 ③에 최애 이름 포함 | 덕질 카드가 사진보다 먼저 렌더, `reasons` jsonb에 `hobby_overlap`·`fav_match` 포함 |
| P2 도현 | 취미 3개만 선택(intensity 1~2) → 퀴즈 3문항 후 스킵 → 덕질 카드 예시 칩으로 채움 → 사진 스킵 → 추천 화면 도달 | 최소 3개로 통과, 스킵 시 `onb_quiz_skip`·`onb_photo_skip` 이벤트 발생, 추천 카드에 "입문 환영" 배지 |
| P3 민재 | `availability` 주말 morning 선택 → region_code 입력 → 데이팅 모드 옵트인(본인인증 mock verify_level=2) → 추천 전원 동일 region → 매칭 → 첫 대화 카드 ②(오프라인)가 1순위 | 교차 모드 추천 0건, 타 지역 추천 0건, 상대 카드에 인증 마크 |
| P4 하은 | 사진 스킵 → 친구 모드 유지 → 매칭 → 채팅에서 전화번호 입력 시 `masked_body`로 마스킹 → 상대가 이미지 전송 시도 → 미인증 상태면 차단 안내 | 마스킹 동작, 모드 전환 권유 푸시 미발송, 신고 버튼 헤더 1탭 |

- 위 4개 중 **P1 시나리오가 Phase 1 게이트의 필수 E2E 1건** 후보(브리프 "가입→인증→매칭→채팅"과 가장 일치). 나머지 3개는 Phase 1 내 수동 QA 체크리스트.
- 각 시나리오는 계정 2개(자기 + 상대)를 seed로 필요 → D1에 페르소나 seed 데이터(닉네임·취미·availability) 4쌍 요청.
