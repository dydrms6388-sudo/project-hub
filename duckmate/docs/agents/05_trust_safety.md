# 05 — 안전/신뢰 정책 (A5)

> 근거: `00_brief.md` 절대 규칙 2(성인 전용·본인인증 게이트), 3(안전 > 성장: 신고/차단/증거보존/24h 조치가 매칭보다 먼저).
> 이 문서는 정책 확정본이다. 구현은 D2(인증)·D4(채팅 마스킹)·D5(신고/제재)·D8(어드민)이 담당하며, 여기 적힌 코드·수치를 **그대로 상수로** 옮긴다.

## 다음 에이전트에게 넘기는 결정사항

- **인증 레벨은 0~3 네 단계로 확정**. `profiles.verify_level` 정수. L0 가입만 / L1 휴대폰 OTP / L2 본인인증(PASS·다날, Phase 1은 mock) / L3 = L2 + 사진 검수 1장 이상 승인. 레벨 산정은 서버 함수 `recompute_verify_level(profile_id)` 한 곳에서만 수행(클라이언트 갱신 금지).
- **채팅·좋아요·추천 노출은 전부 L2 이상**. L0/L1은 온보딩과 자기 프로필 편집만 가능. "미인증 유저 간 DM 금지"는 RLS(`messages` insert 정책)와 API 양쪽에서 체크한다(D2·D4).
- **데이팅 모드는 L3 전용**. 취미 친구 모드는 L2. `profiles.mode='dating'` 전환 시 서버가 `verify_level>=3` 검증.
- **만 19세 미만 차단 3중 체크**: (1) 가입 시 생년월일 입력 → 만 19세 미만이면 `age_blocked` 상태로 진입 차단, (2) 본인인증 결과의 생년월일로 재검증 — 입력값과 불일치 시 인증값 우선 + 자동 신고 큐(`MINOR_SUSPECT`), (3) 인증 CI 값 해시로 재가입 차단. 기준일은 한국 나이가 아닌 **만 나이**, 서버 시간(KST) 기준.
- **신고 사유 코드 14개**(아래 §3 표). `reports.reason_code` 는 이 키의 enum(Postgres `report_reason` 타입)으로 만든다. 클라이언트 라벨은 표의 한국어 라벨을 그대로 쓴다.
- **제재 레벨은 정수 0~5**: 0 없음 / 1 경고 / 2 채팅 제한 24h / 3 정지 3일 / 4 정지 7일 / 5 정지 30일 / 6 영구. `sanctions.level` 은 이 정수. 영구정지는 `profiles.status='banned'` 동시 갱신.
- **자동 제재는 "채팅 제한 24h" 까지만**. 정지(3일 이상)와 영구정지는 반드시 사람이 승인. 단, 미성년 확정(인증 결과 기반)은 즉시 자동 영구 차단 예외.
- **증거 스냅샷은 신고 insert 트랜잭션 안에서** service role 이 생성. 최근 **50개 메시지**(원문 `body` + `masked_body` + `image_path`), 양측 프로필 스냅샷, 사진 경로, 좋아요/매칭 타임스탬프를 `reports.evidence` jsonb 로 저장. 사진 파일 자체는 `evidence/` 버킷에 복사(원본 삭제와 무관하게 유지).
- **보존 기간**: 신고 처리 완료 후 **180일**, 법적 요청(수사기관 협조 등) 시 사건 종결까지 연장 플래그(`legal_hold=true`). 피신고자·신고자 **탈퇴 후에도 보존**. 탈퇴 시 삭제 대상은 §11 표 참조.
- **SLA**: 접수 → 최초 판정까지 P0 1시간 / P1 6시간 / P2 24시간 / P3 72시간. 24h 경과 미처리 P0~P2 는 어드민 상단 배너 + Slack/이메일 알림(D8).
- **연락처 마스킹은 매칭 후 72시간 동안**만 적용, 이후 자동 해제(단, 어느 한쪽이 L3 미만이면 계속 마스킹). 마스킹은 서버(Edge Function 또는 DB trigger)에서 `masked_body` 생성, 클라이언트는 항상 `masked_body` 만 렌더. 원문 `body` 는 본인+service role 만 읽기.
- **탐지 룰은 Phase 1 룰 기반(정규식+키워드) 전용**. ML/외부 API 없음. 룰 정의는 `packages/db/safety-rules.ts` 단일 파일로 두고, 채팅 파이프라인과 신고 자동분류가 동일 파일을 import 한다.
- **사진 검수는 업로드 즉시 `pending`**, 승인 전까지 본인에게만 보이고 추천/프로필에 노출 안 됨. 반려 사유 코드 7개(§8). 얼굴 검사 어댑터가 `no_face` 반환 시 검수 큐에 플래그만 붙이고 자동 반려하지 않는다(Phase 1 오탐 방지).
- **차단은 즉시·양방향·무통보**. 차단 시 활성 매칭은 `status='blocked'` 로 종료되고 양쪽 채팅 목록에서 사라진다(피차단자에게는 "대화가 종료되었습니다" 만 표시). 차단 해제는 차단자만 가능하나, 해제해도 매칭은 복구되지 않는다.
- **차단·제재 상태는 추천 생성(D3)에서 필터**: `blocks` 양방향 + `sanctions` 활성(level≥3) + `profiles.status!='active'` 인 프로필은 추천 후보에서 제외.
- **이의신청은 제재 통보 후 7일 이내 1회**, 어드민이 72시간 내 답변. 이의신청 중에도 제재는 유지.
- **안전 가이드 노출 트리거 2개**: 첫 매칭 성사 직후(모달 1회, 확인 필수) / 채팅에서 오프라인 만남 키워드 감지 시(인라인 배너, 매칭당 1회). 문구는 §10 확정본 사용.
- **어드민 권한 분리**: `moderator`(신고 처리, 경고·채팅제한·3일 정지까지) / `admin`(7일 이상 정지·영구·이의신청 판정·데이터 삭제). 모든 판정은 `audit_logs` 에 actor·before/after 기록.
- **개인정보 다운로드 요청**은 Phase 1 에서는 문의 폼 접수 → 어드민이 수동 JSON export(§11 항목표). 자동화는 Phase 4.

## 1. 인증 레벨 정의

| 레벨 | 이름 | 달성 조건 | 갱신 시점 |
|---|---|---|---|
| 0 | 가입 | 이메일/소셜 로그인 + 생년월일 입력(만 19세 이상) + 닉네임 | 가입 완료 |
| 1 | 휴대폰 | L0 + 휴대폰 SMS OTP 검증(Supabase Auth phone) | OTP 성공 |
| 2 | 본인인증 | L1 + `IdentityVerifier` 성공(PASS/다날 → 이름·생년월일·성별·CI/DI 반환). Phase 1 mock 은 개발 환경에서만 성공 반환, 프로덕션 mock 은 **항상 실패**(실 인증 붙기 전 프로덕션에서 L2 승격 금지 → 소유자 판단으로 화이트리스트 예외 가능) | 인증 콜백 |
| 3 | 사진 인증 | L2 + `photos.review_status='approved'` 사진 ≥1 (is_primary) | 검수 승인/반려 시 재계산 |

- 레벨은 **강등될 수 있다**: 유일한 승인 사진이 삭제·반려되면 L3→L2. 휴대폰 변경 시 L1 재검증.
- CI 해시(`sha256(CI + server_salt)`)를 `identity_verifications` 테이블(D1 추가 필요: `user_id, provider, ci_hash, di_hash, verified_at, birth_date, gender`)에 저장. 동일 `ci_hash` 로 활성 계정 1개만 허용(중복 가입·영구정지 회피 방지).

### 2.1 만 19세 미만 차단 지점
1. **가입 폼**: 생년월일 필수. `age < 19` (만 나이, KST 오늘 기준) → 계정 생성하되 `profiles.status='age_blocked'`, 어떤 화면도 진입 불가, "만 19세 이상만 이용할 수 있어요" 안내 후 로그아웃. 30일 후 자동 삭제.
2. **본인인증 콜백**: 인증기관 생년월일로 재계산. 미성년 → 즉시 `banned` + CI 해시 블록리스트 등록 + 기존 매칭 전부 종료 + 사진 삭제. 입력 생년과 인증 생년이 다르지만 둘 다 성인 → 인증값으로 `birth_year` 덮어쓰고 `audit_logs` 기록.
3. **재가입 시도**: 블록리스트 CI 해시 매치 → 인증 단계에서 차단.
4. 성인이라도 **프로필/채팅에서 미성년 시그널** 감지 시 §7.5 룰에 따라 큐 적재.

## 3. 신고 사유 택소노미

| reason_code | 라벨 | 설명(신고 화면 보조문구) | 심각도 | 자동 조치 |
|---|---|---|---|---|
| `SEXUAL_HARASSMENT` | 성희롱·성적 발언 | 원치 않는 성적 메시지, 신체 언급, 성적 사진 요구 | P1 | 피신고자 채팅 제한 24h(신고 2건 이상 누적 시) |
| `ROMANCE_SCAM` | 사기·로맨스 스캠 | 금전 요구, 투자 권유, 급한 사정 호소, 송금 유도 | P0 | 즉시 채팅 제한 24h + 피신고자 전체 활성 채팅에 경고 배너 |
| `MINOR_SUSPECT` | 미성년 의심 | 학생 신분·나이 언급 등 미성년으로 보이는 정황 | P0 | 프로필 비공개(추천 제외) + 재인증 요구 |
| `IMPERSONATION` | 사칭·타인 사진 | 연예인/타인 사진, 다른 사람 행세 | P1 | 해당 사진 `review_status='held'` 로 즉시 비노출 |
| `OFF_PLATFORM_LURE` | 외부 연락 유도 | 카톡/인스타/텔레그램/링크로 이동 유도 | P2 | 없음(3회 누적 시 경고 자동 발송) |
| `COMMERCIAL_SPAM` | 영업·광고 | 상품 판매, 업소 홍보, 다단계 | P1 | 채팅 제한 24h(2건 누적) |
| `HATE_SPEECH` | 혐오·차별 발언 | 성별·지역·장애·인종·성적지향 비하 | P1 | 없음(수동) |
| `STALKING` | 스토킹·집착 | 반복 연락, 매칭 종료 후 재접근, 위치 추궁 | P0 | 신고자↔피신고자 자동 차단 관계 생성 |
| `PII_REQUEST` | 개인정보 요구 | 주소·직장·실명·신분증·계좌 요구 | P1 | 없음(수동) |
| `INAPPROPRIATE_PHOTO` | 부적절한 사진 | 노출, 불법촬영물, 폭력적 이미지 | P0 | 해당 이미지 즉시 비노출(`held`) + 채팅 제한 24h |
| `THREAT_VIOLENCE` | 협박·폭력 | 위해 협박, 자해 유도, 폭력 예고 | P0 | 채팅 제한 24h |
| `FAKE_PROFILE` | 허위 프로필 | 나이·성별·취미 등 명백한 거짓 | P2 | 없음(수동) |
| `NO_SHOW` | 노쇼·약속 불이행 | 이벤트/만남 약속 무단 불참 | P3 | 없음(3회 누적 시 이벤트 참가 제한 30일) |
| `OTHER` | 기타 | 위 항목에 없는 문제(자유 서술 필수) | P3 | 없음 |

- 신고 폼: 사유 1개 선택 + 자유 서술(선택, `OTHER` 는 필수, 500자) + 증거 스냅샷은 자동 첨부(사용자가 고를 필요 없음).
- 동일 신고자→동일 대상 신고는 **24시간 1건** 제한(중복은 기존 신고에 `detail` append). 신고 남용(신고 5건 이상 전부 `dismissed`)은 신고자에게 경고.
- 심각도는 자동 분류 룰(§7)에 의해 **상향만** 가능(하향 불가).

### 4.3 누적 규칙(자동)
- **서로 다른 신고자 3명**이 30일 내 동일인을 신고(사유 무관, `dismissed` 제외) → 자동 채팅 제한 24h + 큐 우선순위 P1 로 상향.
- 서로 다른 신고자 5명/90일 → 담당자 판정 전까지 프로필 비노출(추천 제외) 임시 조치.
- 확정 제재 level≥3 이 12개월 내 3회 → 영구정지 검토 큐(admin 승인 필요).
- 경고(level 1) 는 누적 3회 시 자동 채팅 제한 24h.
- 누적 카운트는 `sanctions` 와 `reports.status='confirmed'` 를 기준으로 계산, 탈퇴·재가입해도 CI 해시 기준으로 이어진다.

### 4.4 자동 vs 수동
- **자동(시스템)**: level 1·2, §3 표의 "자동 조치", §4.3 누적 조치, 미성년 확정 영구정지.
- **수동(사람)**: level 3 이상 전부. 자동 조치는 항상 `sanctions.reason` 에 `AUTO:<rule_id>` 접두어를 붙여 구분하고, 담당자가 신고를 `dismissed` 로 종결하면 자동 조치는 즉시 해제된다.
- 정지 통보 메시지에는 **사유 카테고리·기간·이의신청 방법**을 반드시 포함. 신고자 신원은 절대 노출하지 않는다.

### 4.5 이의신청
1. 정지 화면 → "이의신청" 버튼(제재 통보 후 7일 이내, 제재 1건당 1회).
2. 사유 서술(1,000자) + 선택 첨부 1장 → `appeals` 테이블(D1 추가: `id, sanction_id, profile_id, body, attachment_path, status(pending/accepted/rejected), decided_by, decided_at`).
3. admin 이 72시간 내 판정. 인용 시 제재 삭제 + 강등된 레벨 복구 + 이메일 통보. 기각 시 사유 한 줄과 함께 통보, 재신청 불가.
4. 로맨스 스캠·미성년·불법촬영물 영구정지는 이의신청 시에도 증거 스냅샷을 삭제하지 않는다.

## 5. 증거 보존

### 5.1 스냅샷 구조 (`reports.evidence` jsonb)
```
{
  "schema": 1,
  "captured_at": "...",
  "match_id": "...",
  "messages": [ { "id", "sender_id", "body", "masked_body", "image_path", "created_at", "read_at" } ],   // 최근 50개, 오래된 순
  "reporter": { "profile_id", "nickname", "verify_level", "mode", "created_at" },
  "target":   { "profile_id", "nickname", "birth_year", "gender", "region_code", "bio", "verify_level", "mode", "status", "created_at", "hobbies": [...] },
  "target_photos": [ { "photo_id", "path", "evidence_path", "review_status" } ],
  "relation": { "like_from_target_at", "like_from_reporter_at", "matched_at", "blocked": bool },
  "detector_hits": [ { "rule_id", "message_id", "matched" } ],
  "prior_reports_count": n,
  "prior_sanctions": [ { "level", "reason", "starts_at", "ends_at" } ]
}
```
- 스냅샷은 신고 insert 와 같은 트랜잭션(service role RPC `create_report`)에서 생성. 실패 시 신고 자체가 실패해야 한다(스냅샷 없는 신고 금지).
- 사진은 `evidence/{report_id}/{photo_id}.jpg` 로 복사. 원본 버킷 삭제·탈퇴와 독립.
- 매칭 없이 프로필 화면에서 신고한 경우 `messages: []`, `match_id: null`.

### 5.2 보존 기간
| 상황 | 보존 |
|---|---|
| 신고 `dismissed` 종결 | 종결 후 90일 |
| 신고 `confirmed` 종결 | 종결 후 180일 |
| 영구정지 확정 | 5년(재가입 방지·분쟁 대응) |
| `legal_hold=true` (수사기관·법원·분쟁조정) | 해제될 때까지, 해제 후 90일 |
| 신고자/피신고자 탈퇴 | **영향 없음** — 위 기간 그대로 유지 |
- 만료 삭제는 일 1회 배치(Edge Function cron). 삭제 시 `audit_logs` 에 `evidence_purged` 기록(내용 제외).
- 접근 권한: `moderator`/`admin` 만. 조회 자체를 `audit_logs` 에 남긴다(누가 언제 어떤 신고 증거를 열었는지).

## 6. 24h 조치 SLA 파이프라인

```
접수(create_report RPC)
 → 자동 분류(reason_code 기본 심각도 + 탐지 룰 hit + 누적 카운트 → priority P0~P3)
 → 즉시 자동 조치(§3 표) 적용
 → 우선순위 큐(reports.status='queued', priority, due_at = created_at + SLA)
 → 담당자 배정(status='in_review', handled_by) — 큐 화면에서 "가져오기"
 → 판정(confirmed → sanction 생성 | dismissed → 자동조치 해제 | need_info → 신고자에게 추가 질문)
 → 통보(신고자: "조치가 완료되었어요" 수준만, 피신고자: 제재 내용) + audit_logs
```

| 우선순위 | 대상 | 최초 판정 목표 | 초과 시 |
|---|---|---|---|
| P0 | 스캠·미성년·불법촬영물·협박·스토킹 | **1시간** | 30분마다 admin 알림 |
| P1 | 성희롱·사칭·영업·혐오·개인정보 | **6시간** | 어드민 배너 + 알림 |
| P2 | 외부 유도·허위 프로필·누적 신고 | **24시간** | 어드민 배너 |
| P3 | 노쇼·기타 | 72시간 | 주간 리포트 |

- 공개 약속(company 사이트 "안전과 신뢰" 페이지)은 **"신고 접수 후 24시간 내 1차 조치"** 로만 표기. P3 는 자동 접수 확인 통보를 24시간 내 보내는 것으로 약속을 충족.
- 심야 P0 대응: Phase 1 은 소유자 1인 온콜. 자동 조치(채팅 제한·비노출)가 사람 판정 전 피해 확산을 막는 구조이므로 SLA 초과가 곧 피해 확대는 아니도록 설계.
- 큐 화면(D8) 필수 컬럼: priority, due_at 카운트다운, reason_code, 피신고자 누적 신고수, 탐지 룰 hit 수, 담당자.

## 7. 탐지 룰 (Phase 1, 룰 기반)

모든 룰은 `{ id, category, pattern|keywords, action, scope }` 로 `packages/db/safety-rules.ts` 에 정의. 채팅 메시지 insert 시 서버에서 1회 평가, 결과는 `messages.masked_body` 와 `message_flags`(D1 추가: `message_id, rule_id, created_at`)에 기록. 프로필 bio·fav_note 저장 시에도 동일 룰 평가.

### 7.1 연락처 패턴 — 조치: **마스킹**(`masked_body` 로 치환) + 발신자에게 인라인 안내
| rule_id | 정규식(요지) | 치환 |
|---|---|---|
| `CT_PHONE` | `01[016789][-.\s]?\d{3,4}[-.\s]?\d{4}`, 공백/특수문자 삽입형(`공일공`, `0 1 0`) 포함 | `[연락처 숨김]` |
| `CT_KAKAO` | `(카톡|카카오|kakao|katalk|ㅋㅌ|open\.kakao\.com)` 근처 20자 내 영숫자 ID | `[연락처 숨김]` |
| `CT_INSTA` | `(인스타|insta|ig)\s*[:@]?\s*[\w.]{3,}` 또는 `@[\w.]{3,30}` | `[연락처 숨김]` |
| `CT_TELEGRAM_LINE` | `(텔레|telegram|t\.me/|라인|line\s*id)` + ID | `[연락처 숨김]` |
| `CT_URL` | `https?://`, `www\.`, `[\w-]+\.(com|net|kr|me|link|io)/?` | `[링크 숨김]` |
| `CT_EMAIL` | 표준 이메일 정규식 + `골뱅이`/`at` 변형 | `[연락처 숨김]` |
| `CT_ACCOUNT` | 은행명 + 10~14자리 숫자 | `[계좌 숨김]` + `SC_MONEY` 동시 hit |

- **해제 규칙**: 매칭 `matched_at + 72h` 이후이면서 양쪽 모두 L3 이면 `CT_*` 마스킹 해제(원문 그대로 전달). 그 전에는 마스킹 + "매칭 3일 후부터 연락처를 주고받을 수 있어요" 안내. 해제 이후에도 `message_flags` 는 기록(증거용).
- 마스킹된 메시지도 `body` 원문은 저장(증거). 수신자는 절대 원문을 읽을 수 없다(RLS: `sender_id = auth.uid()` 일 때만 `body` 컬럼 노출, 그 외 `masked_body` 뷰 사용).
- 우회 시도 3회(같은 매칭에서 `CT_*` 3회 hit) → 발신자에게 경고 배너 + `OFF_PLATFORM_LURE` 자동 신고 큐 적재(P2).

### 7.2 금칙어 카테고리 — 조치: 카테고리별
| 카테고리 | 예시 | 조치 |
|---|---|---|
| `BW_SEXUAL` | 노골적 성적 표현 목록(별도 사전 파일, 200~300개) | 첫 hit: 발신자에게 인라인 경고 / 같은 매칭 2회: 메시지 hold(수신자 미전달) + 자동 신고 큐 P1 |
| `BW_HATE` | 성별·지역·장애·성적지향 비하어 | 인라인 경고 + 2회 자동 신고 P1 |
| `BW_VIOLENCE` | 살해·폭행 협박 표현 | 즉시 자동 신고 P0 + 채팅 제한 24h |
| `BW_ILLEGAL` | 마약 은어·불법촬영물 거래 | 즉시 자동 신고 P0 + 메시지 hold |
| `BW_ADULT_BIZ` | 조건·스폰·업소 관련 | 메시지 hold + 자동 신고 P1 |
- 금칙어는 **초성·자모 분리·특수문자 삽입 정규화** 후 매칭(`ㅅㅂ`, `s.e.x` 등). 오탐 방지를 위해 hold 는 2회부터(폭력·불법 제외).

### 7.3 로맨스 스캠 시그널 — 조치: **점수 합산**, 임계치 도달 시 자동 신고 P0 + 상대에게 경고 배너
| rule_id | 시그널 | 점수 |
|---|---|---|
| `SC_MONEY` | 송금·계좌·돈 빌려·급전·상품권·기프티콘 코드 요구 | 3 |
| `SC_INVEST` | 투자·코인·선물·수익·리딩·재테크 권유 | 3 |
| `SC_URGENT` | 급한 사정·병원비·사고·해외·군인·파병 | 2 |
| `SC_OFFAPP` | 매칭 24h 내 `CT_*` hit 2회 이상 | 2 |
| `SC_MASS_LIKE` | 가입 24h 내 좋아요 30회 이상 / 일 좋아요 상한(무료 5·플러스 15·프로 30)의 2배 초과 시도 | 2 |
| `SC_FAST_LOVE` | 매칭 48h 내 "사랑해·결혼·운명" 류 표현 3회 이상 | 1 |
| `SC_TEMPLATE` | 서로 다른 매칭 3개에 동일 문장(30자 이상) 전송 | 3 |
- 프로필당 누적(7일 롤링). **≥5**: 상대방 채팅 상단에 "금전 요구·투자 권유는 사기일 수 있어요" 배너 + 자동 신고 P0. **≥8**: 채팅 제한 24h + 프로필 비노출.
- `SC_MONEY`·`SC_INVEST` 는 단독 hit 만으로 상대에게 배너 노출(점수와 무관).

### 7.4 성희롱 시그널
- `BW_SEXUAL` hit + 상대의 직전 3개 메시지에 거절·불쾌 표현(`싫어`, `하지 마`, `불편`, `그만`) → 즉시 자동 신고 P1 + 발신자 채팅 제한 24h.
- 이미지 전송 직후 상대가 30초 내 대화 이탈·차단 → 이미지 `held` + 검수 큐.

### 7.5 미성년 시그널 — 조치: 프로필 비노출 + 재인증 요구 + 자동 신고 P0
- `MN_SCHOOL`: 고등학교·고딩·야자·수능 준비·중학·학원 다녀요(교사/학원강사 맥락 제외 키워드 `선생`, `강사`, `근무`)
- `MN_AGE`: `1[0-8]살`, `0[6-9]년생`·`1[0-9]년생`(2026 기준 미성년 출생연도 자동 계산), `미성년`
- `MN_PROFILE_MISMATCH`: 사진 검수자가 `minor_suspect` 플래그 → 즉시 비노출
- 2개 이상 룰 동시 hit 또는 `MN_AGE` 단독 → 프로필 비노출·채팅 제한·재인증 요구. 인증 결과 성인 확인 시 자동 복구.

### 7.6 룰 평가 공통
- 평가는 서버에서만. 클라이언트 프리체크(전송 전 "연락처는 매칭 3일 후에" 힌트)는 UX 용이며 우회 가능하므로 보안 근거로 쓰지 않는다.
- 룰 hit 통계(일별 rule_id 카운트, 오탐 신고 수)를 어드민 대시보드에 노출. 오탐률 20% 초과 룰은 `warn_only` 모드로 강등.

## 8. 사진 검수 정책

- 업로드 → 서버 리사이즈(최대 1600px, EXIF 제거) → 얼굴 검사 어댑터 → `review_status='pending'` → 검수 큐(D8). 승인 전 본인에게만 노출, 목표 검수 시간 24h(P2 SLA 와 동일 큐 UI, 별도 탭).
- 프로필 사진 최대 6장, 대표 사진(`is_primary`) 은 **얼굴이 명확히 보이는 본인 사진**만 승인.

| 결과 코드 | 조건 | 처리 |
|---|---|---|
| `approved` | 본인 얼굴 식별 가능, 아래 반려 사유 없음 | 노출, L3 계산 |
| `reject_no_face` | 얼굴 없음/가림(마스크·선글라스로 식별 불가)·뒷모습·풍경 | 대표 사진만 반려. 보조 사진은 허용(취미 사진 등) |
| `reject_not_self` | 연예인·타인·AI 생성·스톡 사진 의심 | 반려 + 2회 누적 시 `IMPERSONATION` 자동 신고 |
| `reject_nudity` | 노출(속옷·수영복 클로즈업 포함)·성적 암시 | 반려 + 경고(level 1). 불법촬영물 의심은 P0 신고 + 즉시 영구정지 검토 |
| `reject_text_contact` | 연락처·SNS ID·QR·링크·워터마크 텍스트 포함 | 반려 + `OFF_PLATFORM_LURE` 카운트 |
| `reject_minor` | 미성년으로 보임(교복·학교 배경 등) | 반려 + `MINOR_SUSPECT` P0 |
| `reject_group` | 다수 인물로 본인 식별 불가 | 대표 사진만 반려 |
| `reject_quality` | 심한 저화질·과도한 필터·스크린샷 | 반려 |
| `held` | 신고·탐지에 의해 임시 비노출(판정 대기) | 판정 후 approved/reject |

- 반려 시 사용자에게 코드별 한국어 안내(예: "대표 사진은 얼굴이 잘 보이는 본인 사진이어야 해요"). 재업로드 무제한이나 24h 내 반려 5회 → 24h 업로드 제한.
- 검수자 화면에 얼굴 검사 결과(`face_count`, `confidence`)를 참고값으로 표시. 자동 반려는 하지 않는다(Phase 1). Phase 4 이후 `reject_no_face` 만 자동화 검토.
- 채팅 이미지(L3, 매칭 24h 후)는 사전 검수 없이 전달하되 수신자 화면에서 **블러 + "보기" 탭**으로 표시, 신고 시 `held`.

## 9. 차단

- 진입점: 프로필 화면·채팅 상단 메뉴·신고 완료 화면("차단도 할까요?" 기본 체크).
- 효과(즉시, 트랜잭션): `blocks` insert → 활성 `matches.status='blocked'` → 양쪽 추천·좋아요·검색·이벤트 참가자 목록에서 상호 비가시 → 진행 중이던 좋아요 삭제. 피차단자에게 차단 사실 통보 없음(채팅방은 "대화가 종료되었습니다" 상태로 남고 입력 불가).
- RLS: `profiles`, `messages`, `daily_recommendations`, `event_rsvps` 조회 정책에 `NOT EXISTS (blocks 양방향)` 조건. 추천 생성(D3)도 후보 쿼리에서 제외.
- 차단 목록: 설정 > 차단 관리에서 닉네임·차단일 표시, 해제 가능. 해제해도 종료된 매칭·삭제된 좋아요는 복구되지 않으며, 재추천은 30일 뒤부터.
- 차단 상한 없음. 단 24h 내 50건 이상 → 이상 행동 플래그(어드민 참고).
- 이벤트: 호스트를 차단했으면 해당 이벤트 비노출, 참가자 간 차단이면 참가자 목록에서 서로 비노출(호스트에게는 표시).
- **아는 사람 차단(연락처 기반)**: Phase 4(앱 래핑) 후순위. 설계 원칙만 확정 — 연락처는 기기에서 해시(`sha256(E.164)`)하여 업로드, 서버는 해시만 저장, 상대 휴대폰 해시와 매칭되면 양방향 비노출. 원문 연락처 서버 전송 금지.

## 10. 안전 가이드 문구 (확정본)

### 10.1 첫 매칭 성사 직후 (모달, 1회, "확인했어요" 필수)
> **매칭을 축하해요! 대화 전에 3가지만 기억해 주세요.**
> 1. 연락처는 매칭 3일 후부터 주고받을 수 있어요. 그 전엔 여기서 충분히 대화해 보세요.
> 2. 돈 이야기(송금, 투자, 상품권)가 나오면 그건 대화가 아니라 신호예요. 바로 신고해 주세요.
> 3. 불편하면 언제든 차단할 수 있어요. 상대에게 알림이 가지 않아요.
> 신고는 24시간 안에 확인해요.

### 10.2 오프라인 만남 제안 감지 시 (채팅 인라인 배너, 매칭당 1회, 트리거: `만나(자|요|볼)`, `보자`, `오프`, `약속`, `어디서 볼` + 장소/시간 표현)
> **처음 만나는 날, 이렇게 해요.**
> - 사람 많은 공개 장소에서, 낮이나 이른 저녁에 만나요.
> - 친구에게 누구를 어디서 만나는지 알려 두세요.
> - 이동은 각자, 첫 만남에 술은 가볍게.
> - 뭔가 이상하면 그냥 나와도 괜찮아요. 이유를 설명할 필요 없어요.
> [만남 안전 가이드 전체 보기]

### 10.3 스캠 시그널 배너 (상대 화면, `SC_MONEY`/`SC_INVEST` hit 시)
> 이 대화에서 금전·투자 관련 표현이 감지됐어요. 매칭 상대에게 돈을 보내거나 투자 앱을 설치하지 마세요. 의심되면 [신고하기].

### 10.4 마스킹 안내 (발신자 화면)
> 연락처·링크는 매칭 3일 후부터 보낼 수 있어요. 상대에게는 `[연락처 숨김]` 으로 보여요.

### 11.2 데이터 다운로드(개인정보 열람·이동권) 항목
- 프로필(닉네임·생년·성별·지역·bio), 취미·최애·퀴즈 응답, 가용시간, 사진 목록(파일 포함), 본인이 보낸 좋아요, 매칭 목록(상대는 닉네임만), **본인이 보낸 메시지 원문**(상대 메시지는 제외), 본인이 제출한 신고 목록(결과 포함, 피신고자 정보 제외), 본인에게 내려진 제재 목록, 결제·구독 내역, 이벤트 참가 기록, 게임 프로필·퀘스트.

- Phase 1: 문의 폼 → 어드민 수동 JSON export, 10일 이내 이메일 전달. Phase 4: 설정 화면 자동 생성.
