## 다음 에이전트에게 넘기는 결정사항

D6(결제 백엔드)·E4(프로필/구독 UI)가 그대로 구현할 수 있도록 확정한 사항이다.

### 1. 티어/가격 (확정)

| 항목 | 값 |
|---|---|
| 티어 enum | `free` / `plus` / `pro` (DB `subscriptions.tier`) |
| 가격 | 플러스 **₩9,900/월**, 프로 **₩19,900/월** (VAT 포함가, 표시가=결제가) |
| 결제 주기 | 월 단위 자동갱신만 (연간 플랜은 Phase 4 이후 검토, 지금 만들지 않음) |
| 결제 수단 | Toss Payments 빌링키 (Phase 3), RevenueCat IAP (Phase 4) |
| 무료 체험 | **없음** (§6 조정안, 아래 근거) — 대신 첫 구독 첫 달 할인 없음, 가격 단일화 |
| 티어 혜택 상수 | `packages/db`에 `TIER_LIMITS` 상수로 단일 정의 (아래 표 값 그대로). FE/BE/Edge Function 모두 이 상수만 참조 |

### 2. 티어 한도 상수 (`TIER_LIMITS` — 코드 반영값)

```ts
// packages/db/src/tier-limits.ts (D6이 생성)
export const TIER_LIMITS = {
  free: { dailyRecs: 5,  dailyCards: 1, seeLikers: 'blur',  weeklySuperlikes: 1,  battleDetail: 1,   rewind: false, eventPriority: false, ads: true  },
  plus: { dailyRecs: 15, dailyCards: 3, seeLikers: 'open',  weeklySuperlikes: 5,  battleDetail: 5,   rewind: true,  eventPriority: false, ads: false },
  pro:  { dailyRecs: 30, dailyCards: 5, seeLikers: 'open+boost', weeklySuperlikes: 15, battleDetail: -1, rewind: true, eventPriority: true, ads: false },
} as const; // battleDetail: -1 = 전체
```

### 3. 소모성 아이템 (확정)

| item_type | 상품 | 가격 | 만료 |
|---|---|---|---|
| `superlike` | 슈퍼라이크 5개 팩 | ₩4,900 | 구매분 **무만료**, 구독 지급분 **주간 리셋(이월 없음)** |
| `boost` | 부스트 1개 (1시간 노출↑) | ₩3,900 | 구매 후 90일 내 사용 (미사용분 환불 가능 기간과 정합) |

- 차감 순서: **만료 임박분 우선** = 구독 주간 지급분 → 보상 지급분 → 구매분 순.
- 원장은 §6 스키마의 `item_ledger` 테이블 그대로, append-only. 상세 규칙은 본문 2절.

### 4. 구독 상태 머신 (D6 구현 기준)

`none → active → (cancel_scheduled) → expired` / `active → past_due → expired` / 청약철회 시 `active → refunded`.
- 해지 = **기간 말 해지 예약**(`cancel_at = current_period_end`), 즉시 강등 아님. 혜택은 기간 말까지 유지.
- `past_due` 유예 3일(재시도 3회), 이후 `expired` 강등. 유예 중 혜택 유지.
- 청약철회(`refunded`)는 즉시 강등 + 일할 환불 (본문 5절 계산식).

### 5. 다크패턴 가드 (E4·D6 필수 준수)

- 해지 경로: **설정 → 구독 관리 → 해지 = 최대 2뎁스**, 해지 버튼은 구독 관리 화면에 1차 노출.
- 자동갱신 문구: 결제 버튼 **위**에 "매월 ₩N 자동결제, 언제든 해지" 고정 노출. 갱신 3일 전 알림 발송 의무(D7).
- 가짜 신호 금지: 좋아요/매칭 알림은 실제 이벤트 row가 있을 때만. 카운트다운/재고 카피 컴포넌트 자체를 만들지 않는다. 전체 목록은 본문 4절.

### 6. 결제 화면이 필요한 전환 지점 (E4가 페이월 진입점으로 구현)

`likers_blur`(나를 좋아한 사람 블러), `recs_exhausted`(일일 추천 소진), `superlike_empty`(슈퍼라이크 소진), `rewind_attempt`(되돌리기 시도), `battle_detail_lock`(취향 배틀 상세 잠금). 각 지점은 `paywall_source` 파라미터로 로깅. 상세는 본문 3절.

### 7. 환불 (D6 웹훅/어드민 플로우 기준)

- 구독: 결제 후 7일 내 청약철회 가능, 환불액 = `결제액 − 일할사용액 − 소진한 소모성 지급분 정가` (본문 5절 계산식·예시). 7일 경과 후 환불 없음(해지 예약만).
- 소모성: 미사용분만 결제 후 7일 내 철회 가능. 부분 사용 팩은 `결제액 × 미사용수/총수` 환불.

### 1.1 확정 표 (스펙 §6 채택 + 조정 2건)

| 슈퍼라이크 | 주 1개 | 주 5개 | 주 15개 |
| 취향 배틀 결과 상세 | 상위 1명 | 상위 5명 | 전체 |
| 되돌리기 | X | O (일 3회) | O (무제한) |
| 이벤트 우선 참가 | X | X | O |
| 광고 | 배너 (결과/목록 하단 1개) | 없음 | 없음 |
| 부스트 | 구매만 | 구매만 | **월 1개 지급** (조정안) |

### 1.2 조정안 및 근거

| # | 조정 | 근거 |
|---|---|---|
| 1 | **플러스 되돌리기 일 3회 제한** (스펙은 무제한 O) | 되돌리기 무제한이 두 티어 모두에 있으면 프로의 차별점이 "노출/이벤트"뿐이라 2배 가격 정당화가 약함. 플러스 일 3회면 실사용 불편은 없고, 프로 무제한이 "제한 없음" 심리 가치를 가짐. `TIER_LIMITS`에 `rewindPerDay: 3 / -1`로 반영 가능하나, D6 단순화를 위해 v1은 boolean 유지 + FE에서 일 3회 카운트(로컬 아님, `audit` 성격의 서버 카운트) — D6 재량. |
| 2 | **프로 월 부스트 1개 지급** (스펙에 없음) | 프로(₩19,900)는 플러스 대비 정가 기준 +₩10,000인데 스펙 표의 추가 혜택(추천 15↔30, 카드 3↔5, 우선 노출, 배틀 전체, 이벤트 우선)은 체감이 약할 수 있음. 부스트 1개(정가 ₩3,900)를 월 지급하면 "프로 = 매달 ₩3,900 돌려받음" 프레임으로 업셀 카피가 가능하고, 원장 지급 로직(2절)을 그대로 재사용하므로 구현 비용이 거의 0. |
| 3 | **무료 티어의 블러에 인원수 표시** (명시화) | "나를 좋아한 사람 3명" 숫자는 실제 데이터이므로 다크패턴이 아니며(가짜 알림 금지 원칙과 충돌 없음), 최대 전환 트리거. 숫자 0이면 배지 자체를 숨긴다(0명인데 배지를 띄우는 것은 기만). |
| 4 | **무료 체험 미도입** | 체험→자동결제 전환은 자동갱신 인지 실패 민원의 최대 원인이자 다크패턴 경계선. 대신 무료 티어 자체를 "영구 체험판"으로 유지(궁합 카드 매일 1장은 무료에도 반드시 — §5 리텐션 앵커와 정합). |

스펙 표의 나머지 항목(추천 수, 카드 수, 슈퍼라이크 수, 배틀 상세, 광고)은 **그대로 채택**한다. 무료 5명은 매칭 엔진 스펙(D3, 일 추천 무료 5/플러스 15/프로 30)과 이미 정합.

### 1.3 광고 규칙 (무료 티어)

- 배너 1개만: 홈 추천 목록 **하단** 또는 배틀 결과 **하단**. 채팅 화면·온보딩·결제 화면에는 절대 금지.
- 전면 광고(interstitial)·보상형 광고는 v1 미도입. 데이팅 문맥에서 신뢰 훼손이 커 ARPU 대비 손해.

## 2. 소모성 아이템 설계 (원장 관점)

### 2.1 상품 정의

| item_type | 획득 경로 | 수량 | 가격/조건 | 만료 |
|---|---|---|---|---|
| `superlike` | 구매 팩 | 5 | ₩4,900 | 없음 |
| `superlike` | 구독 주간 지급 | 무료1/플러스5/프로15 | 매주 월 00:00 KST 리셋 | **당주 일요일 24:00 소멸, 이월 없음** |
| `superlike` | 퀘스트 보상 (7일 스트릭 등, Phase 2) | 1 | 무료 | 지급 후 30일 |
| `boost` | 구매 | 1 | ₩3,900 | 구매 후 90일 |
| `boost` | 프로 월 지급 (조정안 #2) | 1 | 구독 갱신 시 | 당월 기간 말 소멸 |

### 2.2 원장(`item_ledger`) 규칙 — D6 구현 기준

스키마(§4): `item_ledger(id, user_id, item_type, delta, balance_after, ref)`. 여기에 D6이 컬럼 2개를 추가한다: `bucket`(`purchase`/`grant_sub`/`grant_reward`), `expires_at`(nullable). 사유는 차감 순서·만료·환불 계산이 버킷 없이는 불가능하기 때문.

| 규칙 | 내용 |
|---|---|
| **Append-only** | 원장 행은 수정/삭제 금지. 정정은 반대 부호의 새 행(`ref`에 원 행 id). |
| **잔액** | `balance_after`는 트랜잭션 내에서 계산·기록. 실제 사용 가능 잔액 = `SUM(delta) WHERE expires_at IS NULL OR expires_at > now()` — 만료분 제외 뷰(`item_balances`)를 Postgres view로 제공. |
| **지급 (+)** | ① 구매: Toss 웹훅 검증 성공 시에만 (+5, bucket=purchase, ref=payment_id). 클라이언트 요청만으로 지급 절대 금지. ② 구독 지급: 주간 cron(D7)이 활성 구독자에게 지급, 지급 전 **이전 주 grant_sub 잔여분을 만료 차감 행으로 소멸**(음수 행, ref='weekly_reset'). ③ 보상: 퀘스트 완료 트리거, 멱등키 = `(user_id, quest_id, date)`. |
| **차감 (−)** | 사용 시점에 −1. **차감 순서 = expires_at 오름차순 (NULL 마지막)** → 구독 지급분 → 보상분 → 구매분 순으로 자연 소진. 잔액 0이면 차감 실패 → 페이월(3절 트리거 ③). |
| **멱등성** | 모든 지급/차감은 멱등키(`ref` unique 제약) 필수. 웹훅 재전송·더블탭에도 중복 지급/차감 없음. |
| **동시성** | 차감은 `SELECT ... FOR UPDATE` 또는 Postgres 함수 내 advisory lock. 잔액 음수 불가 CHECK. |
| **환불 (−)** | 환불 승인 시 미사용 구매분을 음수 행으로 회수(ref=refund_id). 잔액 < 회수량이면(이미 사용) 환불 불가분으로 계산 — 5절 참조. |
| **RLS** | 유저는 자기 원장 **읽기만**. 쓰기는 전부 service role(Edge Function). |
| **부스트 동작** | 사용 시 `boost_active_until = now() + 1h`를 프로필에 기록, 매칭 엔진(D3)이 해당 시간 노출 가중치 부여. 활성 중 중복 사용 차단(UI에서 버튼 비활성 + 서버 검증). |

## 3. 무료 유저가 결제할 이유 5개 (전환 트리거)

각 항목의 "트리거"는 E4가 페이월 시트를 띄우는 정확한 화면/순간이고, `paywall_source` 값으로 로깅한다.

| # | 결제할 이유 | 전환 트리거 (화면/순간) | source | 유도 상품 |
|---|---|---|---|---|
| 1 | **나를 좋아한 사람이 누군지 보고 싶다** — 가장 강한 데이팅앱 전환 동기 | 홈 상단 "나를 좋아한 사람 N명" 배지 → 탭하면 블러 그리드 화면. 블러 카드 탭 순간 페이월. **N ≥ 1일 때만 배지 노출** (0명 배지 금지) | `likers_blur` | 플러스 |
| 2 | **오늘 추천 5명이 다 별로였다 / 더 보고 싶다** | 홈에서 일일 추천 5명 소진 후 "내일 만나요" 카드 도달 순간. 카드 하단에 "플러스는 15명" 1줄 + 버튼. 강제 모달 금지, 인라인 카드만 | `recs_exhausted` | 플러스 |
| 3 | **꼭 잡고 싶은 상대에게 슈퍼라이크를 쓰려는데 없다** | 상대 프로필/덕질카드에서 슈퍼라이크 버튼 탭 → 잔액 0 → 바텀시트: "팩 ₩4,900" 구매 + "플러스는 주 5개" 병기. 궁합 %가 높은 상대 앞에서 뜨는, 감정 온도가 가장 높은 순간 | `superlike_empty` | 팩(즉시) / 플러스 |
| 4 | **실수로 넘긴 사람을 되돌리고 싶다** | 패스 직후 3초간 노출되는 "되돌리기" 언도 버튼 탭 순간 (무료는 버튼이 잠금 아이콘). 이미 지나간 후회 감정 = 즉시 전환 압력. 단, "그 사람 다시 못 봐요" 류 협박 카피 금지 — "플러스에서 되돌릴 수 있어요"만 | `rewind_attempt` | 플러스 |
| 5 | **취향 배틀에서 나랑 87% 같은 선택을 한 사람들을 다 보고 싶다** | 배틀 결과 화면: 상위 1명 공개 + "나와 통한 사람 N−1명 더" 잠금 리스트 탭 순간. 게임(Phase 2)이 만드는 자연 전환점 — 게임이 재미로 유입시키고 결과가 페이월로 연결 | `battle_detail_lock` | 플러스/프로 |

공통 규칙: 페이월은 **유저 액션에 대한 응답으로만** 표시(세션 시작 시 자동 팝업 금지), 닫기 버튼은 항상 첫 화면에 보이며, 같은 source 페이월은 **일 1회 초과 자동 재노출 금지**(유저가 직접 탭한 경우는 예외).

## 5. 환불 정책 (전자상거래법 청약철회 기준)

### 5.1 원칙

- **청약철회 기간**: 결제일로부터 **7일** (전자상거래법 §17). 디지털 콘텐츠라도 "사용분 차감 후 환불"을 자발 정책으로 채택 — "즉시 사용 시작 = 철회 불가" 조항으로 전면 거부하지 않는다(민원·심사 리스크 회피, B1/B2 약관과 정합 필요).
- 7일 경과 후: 환불 없음. 구독은 기간 말 해지 예약만 가능.
- 서비스 귀책(장애·오과금·중복결제): 기간 무관 **전액 환불**, 사용분 차감 없음.
- 제재(banned) 유저: 위반에 따른 강제 탈퇴여도 **미사용 기간·미사용 아이템은 환불**한다(몰수 금지 — 약관 무효 리스크).

### 5.2 구독 환불 계산식 (7일 내 청약철회)

```
사용일수 d = ceil((철회시각 − 결제시각) / 24h)   // 최소 1일
일할사용액 = 월요금 × d / 30                      // 고정 30일 기준, 원단위 절사
지급아이템사용액 = Σ (해당 결제로 지급된 소모성 grant_sub 중 사용한 개수 × 정가단가)
                  // 슈퍼라이크 정가단가 = ₩980 (₩4,900/5), 부스트 = ₩3,900
환불액 = max(0, 월요금 − 일할사용액 − 지급아이템사용액)
```

**예시** — 플러스(₩9,900) 결제 5일차 철회, 그 주 지급 슈퍼라이크 5개 중 2개 사용:
`일할 = 9,900 × 5/30 = 1,650` / `아이템 = 2 × 980 = 1,960` / `환불 = 9,900 − 1,650 − 1,960 = ₩6,290`.

- 환불 즉시 `refunded` 상태 전이 + free 강등, 잔여 grant_sub 아이템은 음수 행으로 전량 회수.
- "나를 좋아한 사람 공개"처럼 소모되지 않는 혜택은 일할사용액에 이미 포함된 것으로 보고 별도 차감하지 않는다(이중 차감 금지).

### 5.3 소모성 아이템 환불 계산식 (7일 내)

```
슈퍼라이크 팩: 환불액 = 4,900 × 미사용개수 / 5        // 원단위 절사
부스트:       사용 전 = 전액(₩3,900), 사용(활성화) 후 = 0
```

- "미사용개수"는 원장 기준: 해당 결제 ref의 purchase 버킷 잔여량. 차감 순서(2.2)가 구독 지급분 우선이므로, 구매 직후 며칠 사용해도 구매분이 보존되어 유저에게 유리 — 의도된 설계.
- 환불 승인 시 미사용분을 음수 행으로 회수 후 PG 부분취소 호출. PG 취소 성공 웹훅 확인 후에만 원장 확정(실패 시 보상 트랜잭션).

### 5.4 D6 구현 체크리스트

1. 환불 신청 폼(앱 내) → `refund_requests` 테이블(어드민 큐 D8 연동) — 상태: requested/approved/rejected/done.
2. 계산식은 서버 함수 단일 구현(`calc_refund(payment_id, at)`), 어드민 화면과 유저 안내 화면이 같은 함수 결과를 표시.
3. 모든 환불 처리 `audit_logs` 기록. 처리 SLA 영업일 3일, 지연 시 어드민 큐 경고.

## 6. 앱스토어 IAP 전환 (Phase 4) 가격 티어 매핑 초안

전제: Phase 4에서 Capacitor 래핑 + RevenueCat. 스토어 내 결제는 IAP 의무(B3 검토 결과 반영 필요), **앱 내에서 웹 결제 유도 문구/링크 금지**(Apple 3.1.1 — 위반 시 심사 거절). 웹은 Toss 유지 → 동일 유저가 채널만 다르게 결제하는 구조, 구독 상태는 RevenueCat entitlements + Supabase `subscriptions.provider`로 통합.

### 6.1 가격 매핑 초안 (Apple 가격표는 변동 가능 — Phase 4 시점 재확인 필수)

| 상품 | 웹(Toss) | App Store/Play 초안 | 비고 |
|---|---|---|---|
| 플러스 월 | ₩9,900 | **₩12,000** | 수수료 15~30% 흡수를 위해 스토어가를 상향. 동일가(₩9,900) 시 마진 최대 ₩2,970 손실 |
| 프로 월 | ₩19,900 | **₩25,000** | 동상 |

- 대안: 스토어/웹 동일가 정책(가격 신뢰 우선, 수수료는 마진에서 흡수). **초안은 차등가**를 채택하되 최종 결정은 Phase 4에서 소유자 승인 — 차등가는 유저 인지 시 불만 요인이므로 앱 내에서 웹 가격을 언급하지 않는 것이 전제(어차피 스토어 규정상 금지).

### 6.2 전환 시 규칙

| 항목 | 규칙 |
|---|---|
| 채널 충돌 | 활성 구독 1개만 허용. Toss 활성 상태에서 IAP 구매 시도 → 차단 안내("웹에서 결제한 구독이 있어요. 기간 종료 후 이용 가능"). 반대도 동일 |
