# 04 — 수익 모델 (A4 확정안)

> 담당: A4 수익 모델 · 입력: `00_brief.md` 유료 구조 표 · 소비자: **D6(결제 스키마·Edge Function)**, **E4(구독/상점 UI)**, F그룹(게임 보상 연동), 법무 검토자.
> 이 문서는 코드가 아니라 **계약**이다. 여기 정의한 enum·키·규칙을 D6/E4가 그대로 옮긴다. 변경은 이 문서를 먼저 수정한 뒤 코드에 반영한다.

## 다음 에이전트에게 넘기는 결정사항

- **tier enum 확정**: `subscriptions.tier ∈ {'free','plus','pro'}`. `free`는 DB 행을 만들지 않는다 — 활성 구독 행이 없으면 `free`로 해석 (D6: `get_effective_tier(user_id)` SQL 함수 1개로 통일, 앱 코드에서 tier를 직접 계산하지 말 것).
- **subscriptions.status enum**: `'active' | 'past_due' | 'canceled' | 'expired' | 'refunded'`. `canceled`는 "다음 갱신 안 함, 기간 만료까지 혜택 유지"(`cancel_at` = `current_period_end`). 혜택 즉시 소멸은 `refunded`뿐.
- **권한은 정수/불리언 키 12개로만 표현** (§2 표). 서버(RLS/Edge Function)와 클라이언트가 같은 `ENTITLEMENTS[tier]` 상수 테이블을 `packages/db/src/entitlements.ts`에서 import. UI에서 "플러스면 ~" 같은 tier 비교 금지, 반드시 키 비교(`ent.undo === true`).
- **item_type enum 확정**: `item_ledger.item_type ∈ {'superlike','boost','rewind_pack','card_refill'}`. 구독 지급분과 구매분은 같은 타입, `ref`로 출처 구분(§3). 잔액은 `item_ledger`의 마지막 `balance_after`가 아니라 **`SUM(delta)`**로 계산하고, 동시성은 `user_id` 단위 advisory lock.
- **주간 슈퍼라이크는 잔액이 아니라 쿼터**: 구독 슈퍼라이크(주1/5/15)는 `item_ledger`에 넣지 않고 `weekly_quota_used` 뷰(likes 테이블에서 `type='super'` AND `created_at >= 이번 주 월 00:00 KST` 카운트)로 계산. 사용 순서 = **쿼터 먼저, 구매 잔액 나중** (구매분이 주간 리셋에 증발하지 않게).
- **권한 체크 포인트 8곳** (§2.3): 서버측 필수. 클라이언트 체크는 UX용이며 보안 경계가 아니다.
- **결제 테이블 추가 2개** (D6): `payments(id, user_id, provider, provider_payment_id, kind('subscription'|'item'), sku, amount_krw, status, paid_at, refunded_amount_krw, refunded_at, receipt_url)`, `refund_requests(id, payment_id, user_id, reason_code, computed_deduction_krw, computed_refund_krw, formula_snapshot(jsonb), status, handled_by, handled_at)`. 환불 계산식 스냅샷 보존 필수(분쟁 대비).
- **SKU 문자열 고정**: `plus_monthly`, `pro_monthly`, `superlike_5`, `boost_1h`, `rewind_3`, `card_refill_3`. 가격은 코드가 아니라 `skus` 테이블(`sku, price_krw, item_type, item_qty, is_active, experiment_group`)에서 읽는다 — Phase 3 이후 가격 실험을 위해.
- **해지 = 설정 > 구독 관리 > [구독 해지] 2탭 + 확인 1회**. 확인 다이얼로그에는 "혜택은 {날짜}까지 유지돼요"만 표기, 만류 오퍼 없음. 해지 후 재구독 오퍼는 만료 D-3 알림 1회로 제한.
- **구독 갱신 고지**: 결제 화면에 "매월 {일}에 ₩{금액} 자동 결제, 언제든 해지" 문구를 결제 버튼 **위**에 고정 노출. 갱신 D-7 이메일/푸시 1회 필수(전자상거래법·공정위 다크패턴 규제 대응).
- **광고는 무료 티어 + 추천 목록 하단 1슬롯 + 결과형 화면 1슬롯만**. 채팅·온보딩·신고·인증·결제·프로필 상세에서는 절대 렌더 안 함(§9). 광고 컴포넌트는 `AdSlot` 하나로 통일하고 `ent.ads === false`면 렌더 자체를 생략(공간도 남기지 않음).
- **환불 계산은 서버 단일 함수** `compute_refund(payment_id, requested_at)` (Edge Function) — 클라이언트 계산 금지. §6 공식과 예시를 D6가 단위 테스트로 그대로 옮긴다.
- **Phase 3까지는 모든 유료 경로를 feature flag `PAYMENTS_ENABLED=false`** 뒤에 둔다. 플래그 off 상태에서 UI는 "준비 중" 배지만 표기하고 결제 버튼을 노출하지 않는다 (브리프 규칙 1).
- **가짜 신호 절대 금지**: "누군가 당신을 좋아해요" 알림은 실제 `likes` 행이 있을 때만, 그리고 블러 카운트는 실제 수. 구현체에 상수/랜덤 값이 들어갈 수 없도록 D6가 알림 발송 함수의 입력을 `like_id`로 강제.

## 1. 원칙

1. **구독은 "더 많이", 소모성은 "지금 한 번"** — 같은 혜택을 두 방식으로 파는 건 허용하되, 무료 티어를 일부러 불편하게 만들지 않는다. 무료 5명 추천은 "쓸 만한" 수준이어야 하고, 매칭·채팅·신고는 티어 무관 동일 품질이다.
2. **안전 기능은 절대 유료화 안 함**: 신고, 차단, 사진 검수, 본인인증, 채팅 마스킹 — 전부 무료 티어 포함. 인증 배지도 유료가 아니다.
3. **"보이는 것"은 팔되, "속이는 것"은 팔지 않는다** — 좋아요 수 부풀리기, 노출 조작 미고지 금지. 부스트는 상대에게도 "부스트 중" 아이콘으로 표시.
4. 게임 보상(스트릭 7일 = 슈퍼라이크 1개 등)은 소모성 아이템과 **같은 ledger**를 쓴다. 무료 유저도 아이템을 "벌 수" 있어야 결제가 강요로 느껴지지 않는다.

**조정 근거**
- *조정 1 (읽음 표시)*: 브리프 표에 없으나 데이팅 앱 유료 전환의 검증된 동인. 단, 무료 유저가 **보낸** 메시지의 읽음 여부만 숨기고, 상대가 유료면 상대에게는 보인다(비대칭 허용). 채팅 품질 자체는 손대지 않는다.
- *조정 2 (필터)*: 무료 필터는 "모드·성별·연령대·광역 지역"까지. 활동 시간대 겹침·세부 지역·취미 강도 필터는 플러스부터. 매칭 점수 산식(D3)은 티어 무관 동일 — 필터는 후보 풀만 좁힌다.
- 프로 전용 혜택이 브리프에서 얇았음(우선노출·이벤트뿐). `profile_stats`를 추가하되 "누가 봤는지"가 아니라 **집계 숫자만** 제공해 스토킹 우려 차단.
- 슈퍼라이크 "주15"(프로)는 유지. 단 하루 상한 5개(`daily_superlike_cap=5`, 티어 공통) — 스팸 방지.

## 3. 소모성 아이템

| 아이템 | `item_type` | SKU | 가격 | 수량 | 만료 | 비고 |
|---|---|---|---|---|---|---|
| 슈퍼라이크 | `superlike` | `superlike_5` | ₩4,900 | 5 | **없음** (구매분 영구) | 구독 쿼터 소진 후 사용. 일 상한 5 공통 |
| 부스트 1시간 | `boost` | `boost_1h` | ₩3,900 | 1 | 구매 후 **90일** 내 미사용 시 소멸 (구매 시 명시) | 활성 중 재사용 불가(중첩 금지). 발동 시각 유저 선택 |
| 되돌리기 3회권 *(추가 후보 A)* | `rewind_pack` | `rewind_3` | ₩1,900 | 3 | 없음 | 무료 유저용. `undo` 권한이 있는 티어는 구매 버튼 숨김 |
| 궁합 카드 리필 3장 *(추가 후보 B)* | `card_refill` | `card_refill_3` | ₩1,500 | 3 | **당일 자정(KST)** 소멸 — 구매 화면에 큰 글씨 고지 | 게임(F) 연동. 일 최대 1회 구매(하루 카드 상한 = 티어 한도 + 3) |

**ledger 규칙**
- `delta > 0` 출처를 `ref`에 기록: `purchase:{payment_id}` / `sub_grant:{subscription_id}:{period}` / `quest:{quest_progress_id}` / `refund_reversal:{refund_id}` / `admin:{audit_log_id}`.
- 소비(`delta < 0`) 시 `ref = 'use:{like_id|boost_id|...}'`. **차감 순서 = 만료 임박분 → 퀘스트 보상분 → 구매분** (FIFO by expiry, 그다음 무료분 우선 소진 — 환불 시 구매분이 남아 있도록).
- 만료는 배치가 `delta<0, ref='expire:{원 purchase ref}'`를 넣어 처리(행 삭제 금지).
- 부스트 아이템은 "보유 1개"를 ledger에 두고, 발동 시 `boosts` 행 생성 + ledger `-1`.

**환불 시 차감**: 구매 묶음 중 **사용한 개수 × (묶음가 ÷ 수량)**을 차감. 예: 슈퍼라이크 5개(₩4,900) 중 2개 사용 → 차감 ₩1,960, 환불 ₩2,940. 환불 승인 시 남은 미사용분은 ledger에서 `refund_reversal`로 회수. 부스트는 발동 즉시 "사용"(1시간 중 몇 분 남았든 전액 사용 처리 — 결제 화면에 명시).

## 4. 무료 유저가 결제하는 자연스러운 순간 5개

| # | 동기 | 화면·순간 | 노출 방식 (강요 없음) |
|---|---|---|---|
| 1 | **"나를 좋아한 사람이 있는데 누군지 모른다"** | 좋아요 탭, 실제 like가 1건 이상 있을 때만 | 블러 카드 + "3명이 좋아해요 · 플러스로 확인" 텍스트 버튼. like 0건이면 유료 안내 자체가 없음 |
| 2 | **오늘 추천 5명을 다 봤는데 괜찮은 사람이 있었을 것 같다** | 추천 탭 끝 화면 ("오늘 추천 끝") | "내일 5명 더 와요" 가 기본 문장. 그 아래 작은 링크 "플러스는 하루 15명". 카운트다운·재촉 없음 |
| 3 | **실수로 패스했다** | 패스 직후 5초간 하단 스낵바 | 무료: "되돌리기는 플러스 혜택이에요 · 3회권 ₩1,900" 두 선택지. 5초 후 사라지고 다시 띄우지 않음 |
| 4 | **덕질 태그가 정확히 겹치는 사람을 발견 → 확실히 눈에 띄고 싶다** | 프로필 상세, 취미 자카드 ≥ 0.6인 카드에서 | 슈퍼라이크 버튼은 항상 존재. 쿼터 0이면 누른 뒤 "이번 주 쿼터 다 썼어요 · 5개 ₩4,900 / 스트릭 7일이면 1개 무료" 시트. 구매와 무료 획득 경로 **동등 크기**로 표시 |
| 5 | **주말 이벤트(취미 오프라인 모임)에 참가하고 싶은데 마감이 빠르다** | 이벤트 상세, 우선기간 중 | "프로 회원 우선 접수 중 · 일반 접수는 {시각}부터" 사실만 표기. 남은 좌석 수는 실제 값, 없으면 표시 안 함 |

부스트는 별도로 홈 상단 "지금 활동 중인 사람 많아요" 같은 문구로 팔지 않는다. 부스트 진입점은 **상점 탭**과 프로필 편집 완료 화면(사진 검수 통과 직후, "새 프로필로 눈에 띄고 싶다면") 두 곳만.

## 6. 환불·청약철회 정책

**법적 기준**: 전자상거래법 제17조 — 결제일로부터 **7일 이내** 청약철회. 디지털 콘텐츠 중 "사용분"은 차감 가능(사전 고지 + 사용 개시 시점 명확). 7일 경과 후에도 **서비스 장애·오과금·미성년 결제**는 전액 환불. 앱 IAP(Phase 4)는 스토어 정책이 우선하며 앱 내 안내로 스토어 환불 경로를 연결.

### 6.1 계산식 (`compute_refund`)

**구독** (월정액, 결제일 `P`, 요청일 `R`, 기간 일수 `D`=해당 달 일수, 월요금 `F`):
```
사용일수 U = max(1, floor((R - P) / 1day) + 1)   -- 결제 당일도 1일 사용
차감액    = round(F × U / D)
환불액    = F - 차감액
조건: R - P ≤ 7일 → 위 공식. 7일 초과 → 원칙 환불 불가(잔여 기간 혜택 유지). 예외 사유는 전액.
```
구독 기간 중 소모성 지급분(주간 슈퍼라이크 쿼터)은 이미 "사용일수"에 포함된 것으로 보고 별도 차감하지 않는다(이중 차감 금지).

**소모성 아이템** (묶음가 `F`, 수량 `Q`, 사용 수량 `u`, 만료 소멸분 `e`):
```
단가      = F / Q
차감액    = round(단가 × u)          -- 만료 소멸분 e는 차감하지 않음 (7일 내에는 만료가 발생하지 않도록 만료 ≥ 90일 또는 당일 소멸 아이템은 구매 당일 청약철회만 허용)
환불액    = F - 차감액
card_refill(당일 소멸): 1장이라도 사용 시 환불 불가, 미사용 상태로 당일 요청 시 전액.
boost: 발동 전 전액, 발동 후 0 (사용 개시 = 전량 사용, 결제 화면 고지).
```

### 6.2 예시

1. **플러스 구독, 3일째 환불**: 9/1 결제 ₩9,900, 9/3 요청. U=3, D=30 → 차감 round(9,900×3/30)=₩990 → **환불 ₩8,910**. 구독 `status='refunded'`, 즉시 free 전환, 미사용 주간 쿼터 소멸.
2. **슈퍼라이크 5개 중 2개 사용, 5일째**: ₩4,900, u=2 → 단가 980 → 차감 ₩1,960 → **환불 ₩2,940**. ledger에 `refund_reversal` -3 기록. 잔액이 이미 3 미만이면(퀘스트분 먼저 소진 규칙 덕에 드물지만) 실제 회수 가능 수량 기준으로 환불액 재계산: 환불액 = 단가 × 회수 수량.
3. **부스트 구매 후 발동 40분 경과, 당일 요청**: 발동 = 사용 개시 → **환불 ₩0**. 단, 발동 중 서버 장애로 노출 가중치가 적용되지 않았음이 로그로 확인되면 전액 ₩3,900 (사유 코드 `service_fault`).

### 6.3 운영 규칙
- 요청 접수 → 자동 계산 → **3영업일 내** PG 환불 실행(Toss 부분취소 API). `refund_requests.formula_snapshot`에 U/D/u/단가 저장.
- `reason_code ∈ {'change_of_mind','service_fault','duplicate_charge','minor','other'}`. `service_fault`/`duplicate_charge`/`minor`는 7일 규칙·차감 미적용.
- 환불 후 30일 내 동일 SKU 재구매 시 환불 이력 표시(운영자 화면만) — 어뷰즈 탐지용, 유저 제재 근거로는 단독 사용 금지.

## 7. 가격 실험 계획 (Phase 3 이후)

**A/B 대상 (허용)**
- 플러스 가격 ₩7,900 / ₩9,900 / ₩11,900 — 신규 가입 코호트 단위로 배정(`skus.experiment_group`), 기존 구독자 가격 불변.
- 연간 플랜 도입 여부(월 환산 20% 할인) — 노출 위치만 실험, 자동 선택 없음.
- 슈퍼라이크 묶음 수량(5개 ₩4,900 vs 10개 ₩8,900) — 두 SKU 병행 노출 vs 단일.
- 유료 진입점 문구 톤(§4 표의 "사실 문장" 범위 내에서만 2안).
- 7일 무료 체험 유무 — 체험 시 §5-6 알림 규칙 필수.

**절대 하지 않는 실험**
- 같은 시점에 **같은 코호트** 안에서 유저별 다른 가격(개인화 가격) — 가격 차별 논란·신뢰 훼손.
- 무료 티어 한도를 낮춰 전환율을 재는 실험(추천 5명 → 3명 등). 무료 하한은 이 문서의 표가 바닥.
- 긴급/공포 카피, 카운트다운, 가짜 재고 표시를 변수로 두는 실험.
- 해지 플로우 마찰(뎁스·확인 횟수)을 늘리는 실험.
- 안전 기능(신고/차단/인증)을 유료 변수로 두는 실험.
- 실험 결과가 유의해도 **환불율·신고율·D30 리텐션**이 악화되면 채택 금지(가드레일 지표).

## 8. 단위경제 가설

**공통 가정** (Phase 3 개시 6개월 후 기준, 출처: 국내 데이팅 앱 공개 지표 및 일반적 F2P 벤치마크 — 검증 전 가설)
- 인증 완료 MAU를 분모로 사용(미인증은 결제 불가).
- 구독자 티어 믹스: 플러스 75% / 프로 25%.
- 구독 ARPPU(월) = 9,900×0.75 + 19,900×0.25 = **₩12,400**. PG 수수료 3.3%·앱스토어(Phase 4) 15~30%는 별도 차감(아래 매출은 총매출).
- 소모성: 결제 유저 중 30%가 월 1회 추가 구매, 평균 ₩4,500 → 결제 유저당 +₩1,350. **총 ARPPU ≈ ₩13,750**.
- 광고: 무료 MAU × 월 20세션 × 세션당 1.5 노출 × eCPM ₩1,500 ÷ 1,000 ≈ 무료 유저당 **₩45/월** (데이팅 카테고리 eCPM 저조 반영).
- 월 구독 이탈률 12% (평균 구독 유지 ≈ 8개월).

| 시나리오 | 인증 MAU | 유료 전환율 | 결제 유저 | 구독+아이템 매출 | 광고 매출 | **월 총매출** |
|---|---|---|---|---|---|---|
| 보수 | 10,000 | 2.0% | 200 | ₩2,750,000 | ₩441,000 | **≈ ₩3.2M** |
| 기본 | 30,000 | 3.5% | 1,050 | ₩14,437,500 | ₩1,303,000 | **≈ ₩15.7M** |
| 낙관 | 80,000 | 5.0% | 4,000 | ₩55,000,000 | ₩3,420,000 | **≈ ₩58.4M** |

- 손익 참고: Supabase Pro + Vercel Pro + 본인인증 건당 ₩300(포트원 PASS 기준, 가입 시 1회) + 사진 검수 인건비. 기본 시나리오에서 인증 비용은 월 신규 8,000명 × ₩300 = ₩2.4M — 매출 대비 15%. 인증을 무료로 제공하는 정책은 유지(안전 > 성장)하되 Phase 4에서 재검토.

## 9. 광고 정책 (무료 티어)

**위치 (허용 2슬롯)**
1. 추천 탭 — 오늘 추천 카드를 **모두 넘긴 뒤** 나오는 "오늘 추천 끝" 화면 하단 1개. 추천 카드 사이 삽입 금지.
2. 결과형 화면 — 취향 배틀·궁합 카드 결과 화면 **하단** 1개(허브 정책과 동일: 입력 화면 광고 금지, 결과 하단 1개).

**노출 금지 화면 (코드로 강제 — `AdSlot`이 라우트 allowlist 밖이면 렌더 안 함)**
채팅(목록·방 전부) · 온보딩·가입·연령 확인 · 본인인증 · 사진 업로드/검수 · 신고·차단·고객센터 · 결제·상점·구독 관리 · 프로필 상세(타인) · 좋아요 탭 · 법적 고지 페이지 · 이벤트 RSVP · 에러/빈 상태 화면.

**형식 규칙**
- 배너(320×100 이하) 또는 네이티브 카드 1개. 전면(인터스티셜)·리워드 광고 금지 — 리워드 광고는 "광고 보면 슈퍼라이크"로 이어져 §5-13(무료 유저 감점) 유사 구조가 되므로 Phase 5 이전 도입 안 함.
- 항상 "광고" 라벨 + 앱 카드와 구분되는 배경. 자동재생 영상·소리 금지.
- 유료 전환 즉시(`ent.ads=false`) 슬롯 제거, 레이아웃 시프트 없이.

**AdSense / AdMob 데이팅 카테고리 주의**
- Google 정책상 **데이팅은 "제한 카테고리"**: 성적 암시 콘텐츠·"만남 알선" 톤이면 광고 제한/계정 정지. 앱 설명·랜딩·광고 인접 콘텐츠를 "취미 친구/커뮤니티" 톤으로 유지하고, 광고 슬롯이 있는 화면에 사용자 사진 원본이 크게 노출되지 않도록(결과 화면·추천 끝 화면은 사진 없음).
- UGC(프로필·채팅)는 `noindex`이며 광고도 싣지 않으므로, AdSense 크롤러가 UGC를 볼 일이 없다 — 이 구조를 유지할 것. 광고가 붙는 화면은 로그인 후 화면이라 AdSense(웹)보다 **AdMob(앱, Phase 4)·GAM** 이 현실적. Phase 3 웹 단계에서는 광고 슬롯을 **빈 컴포넌트로 구현만** 하고 실제 네트워크 연결은 Phase 4에서 결정.
- 앱스토어 등록 시 "데이팅" 카테고리는 앱 연령 등급 17+/19+ 필수 → AdMob도 성인 타겟 인벤토리로 설정, 아동 대상(`tag_for_child_directed_treatment`) 절대 false.
- 광고 개인화 동의: 개인정보처리방침에 광고 식별자 항목 추가 + 앱 첫 실행 ATT/동의 다이얼로그. 거부 시 비개인화 광고로 폴백(수익 감소 감수).
- 광고주 카테고리 차단: 성인·도박·대출·외모 시술(성형/다이어트) — 서비스 철학("외모 점수 없음")과 충돌.

## 10. 미결정·후속 과제

- 연간 플랜 도입 여부 → §7 실험 결과 후. 도입 시 `tier`는 그대로, `subscriptions.interval('month'|'year')` 컬럼 추가.
