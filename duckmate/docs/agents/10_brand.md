## 2. 컬러

### 2.1 원칙
- 보라(primary)는 **브랜드·주 액션·인증 신호**, 코랄(accent)은 **좋아요·매칭·축하 등 "감정이 움직이는 순간"**에만. 코랄이 화면의 10%를 넘지 않게 한다(코랄 과다 = 데이팅앱 클리셰).
- 오프화이트(neutral-50)가 앱 배경. 순백(neutral-0)은 카드·시트 표면에만.
- 위험·삭제·신고는 별도 danger 레드. 코랄과 혼용 금지.
- 컬러로만 의미 전달 금지 — 항상 아이콘 또는 텍스트 동반(WCAG 1.4.1).

### 3.1 서체

### 4.2 문체
- **해요체 통일**("~해요", "~돼요", "~할게요"). 반말·"~습니다" 금지. 예외: 법적 페이지·제재 통보·영수증·이의신청 답변은 "~합니다" 허용(공식 문서 톤).
- 주어 "덕메이트는" 대신 "우리"도 쓰지 않는다 — 주어 생략이 기본. 사용자는 "회원님" 금지, 닉네임 또는 생략.
- 느낌표는 화면당 1개 이하, 축하 순간에만. 물음표 버튼("계속할까요?") 금지 — 버튼은 동사형.
- 영어 혼용 최소화: "매칭·프로필·퀴즈·슈퍼라이크"처럼 외래어 정착 단어만. "Like", "Pass" 영문 버튼 금지 → "좋아요" / "넘기기".
- 상대를 지칭할 때 "이성" 금지 → "상대", "이 사람". 성별 언급은 데이팅 모드 설정 화면에서만.

### 4.3 이모지 규칙
- 허용 위치: 헤드라인 끝 0~1개, 빈 상태 일러스트 대체 1개, 취미 카테고리 아바타(§6.3). 본문·버튼·푸시 본문·에러·제재·결제·법적 문구는 0개.
- 허용 세트(브랜드 톤): 🎉 ✨ 👋 🎲 🎮 🎤 📚 ☕ 📷 🏃 ✈️ 🐾 🎵 💻 📺.
- 금지: 😍 😘 🔥 💋 🍑 (외모·유혹 연상), ❤️ 💔 💕 (좋아요는 아이콘), 😭 🥺 (죄책감 유도), 🚨 ⚠️ (경고는 lucide 아이콘으로).

## 5. 로고 / 심볼 / OG

### 5.1 심볼 "덕 마크" — 오리를 유치하지 않게 처리하는 규칙
컨셉: **말풍선과 오리 머리가 한 실루엣**. 말풍선 꼬리가 곧 대화, 오른쪽 코랄 부리가 곧 "같이 할 것" 제안. "duck" 말장난을 심볼이 받아 준다.

1. 눈은 **점 1개**(흰자·눈동자·속눈썹 금지). 눈 크기는 머리 지름의 1/8 이하.
2. **노란색 금지**, 몸통·날개·물결 금지 — 머리 실루엣만. 고무오리·병아리 연상 차단.
3. 색은 primary-600 + accent-500 + neutral-50 **3색 이내**. 그라데이션·광택·그림자 금지.
4. 볼터치·미소·혀·모자 등 표정 요소 금지. 부리는 닫힌 상태의 둥근 쐐기 1개.
5. 기하 구성: 원 1 + 쐐기 1 + 삼각 꼬리 1. 손그림 선·흔들린 윤곽 금지.
6. 최소 크기 16px에서도 부리가 구분돼야 하며, 단색 버전은 부리를 네거티브(배경색)로 뚫는다.

- 인증 마크: `shield-check`(L2 "본인인증", primary 아웃라인 칩) / `badge-check`(L3 "사진인증", primary 채움 칩). "입문 환영": `sprout`, secondary 칩.

### 6.3 사진 없는 프로필 아바타 (생성 규칙)
1. 입력: `profile_id`(해시), rank 1 취미 카테고리, 닉네임 첫 글자(선택).
2. 배경 = 해당 카테고리 bg 색. 전경 = 카테고리 이모지(친구 모드 기본) 또는 lucide 아이콘(설정에서 선택). 이모지 크기 = 아바타 지름의 50%.
3. 변주: `hash(profile_id) % 3`으로 배경에 secondary-200 원형 데코 위치(좌상/우하/없음)만 바꾼다. 색상 자체는 카테고리 고정(같은 취미 = 같은 계열, 한눈에 읽힘).
4. 닉네임 첫 글자 표시는 **옵션 off 기본**(취미가 곧 정체성). 켜면 이모지 대신 글자 1자(Pretendard 700, fg 색).
5. 금지: 사람 실루엣 기본 아바타, 성별 기본 아바타(파랑/분홍), 랜덤 얼굴 생성, 외부 아바타 API. 데이팅 모드는 승인 사진이 필수라 아바타는 친구 모드·채팅 목록·차단 목록에서만 보인다.
6. 결정론적 순수 함수 `avatarFor(profileId, categorySlug)`로 `packages/ui`에 구현(서버 컴포넌트·OG 무관).

## 7. 모션

### 7.1 원칙
- 기본 200ms, 진입 `cubic-bezier(0.2, 0, 0, 1)`, 퇴장 150ms `cubic-bezier(0.4, 0, 1, 1)`. 마이크로(체크·토글·칩 선택) 120ms. 시트·모달 260ms. 카드 뒤집기 320ms(`rotateY`, `backface-visibility: hidden`).
- 움직이는 속성은 `transform`·`opacity`만. `height`·`top` 애니메이션 금지(레이아웃 스래싱·CLS).
- 한 화면에 동시에 움직이는 요소 ≤ 2. 무한 루프 애니메이션은 로딩 스피너·진행 바 스켈레톤만.
- 좋아요 탭: 아이콘 스케일 1 → 1.15 → 1(120ms×2) + 코랄 채움. 파티클·하트 폭죽 금지.
- 스켈레톤: neutral-100 ↔ neutral-200 1.2s 페이드, 3초 초과 시 텍스트 안내("추천을 준비하고 있어요").

### 7.2 reduce-motion
```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: 0.01ms !important; animation-iteration-count: 1 !important; transition-duration: 120ms !important; scroll-behavior: auto !important; }
  .flip-card { transition: opacity 120ms; transform: none !important; }
}
```
- 이동·스케일·회전 제거, opacity 120ms만 유지. 카드 뒤집기는 즉시 교체. 매칭 화면의 카드 겹침 애니메이션은 정지 이미지로 대체(PRD §5.2).
- 설정에 별도 "애니메이션 줄이기" 토글은 두지 않는다(OS 설정 존중).

### 7.3 매칭 리빌 (Phase 2 · F2 구현, 여기서는 스펙만)
- 총 길이 ≤ 1.2s, 어느 시점에도 탭으로 건너뛰기 가능. 순서: 두 덕질 카드가 좌우에서 200ms 진입 → 겹치는 태그가 코랄로 260ms 점등 → 헤드라인 "매칭됐어요 🎉" 200ms 페이드. 스크래치 미니게임은 손가락 이동 거리 기반, 최대 3초 후 자동 공개.
- 소리·햅틱: 햅틱 1회(성공 패턴)만, 소리 없음. reduce-motion이면 리빌 생략하고 결과 화면 즉시.
- 광고·결제 유도가 리빌 앞뒤에 끼어들지 않는다(A4 §5).
