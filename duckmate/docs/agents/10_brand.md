### D-4. 접근성 하드룰 (다크패턴 금지 10항 + PRD §4 AA와 연동)
1. **코랄 배경 + 흰 텍스트 금지** (대비 2.75:1 — FAIL). 코랄이 배경이면 텍스트는 `ink`(6.23:1), 코랄이 텍스트면 라이트에서는 accent-700 이상.
2. 주 CTA는 brand-600 배경 + 백색 텍스트(7.44:1 이상)로 통일. brand-500은 대형 텍스트/그래픽·게이지 채움 전용.
3. 거절/닫기 버튼은 수락 버튼 대비 최소 70% 크기, 동일 위계의 시각적 가시성(PRD C1~C4 지시 승계).
4. 상태 전달은 색상 단독 금지 — 아이콘/텍스트 병행(궁합 게이지 포함).

### D-5. 타이포그래피 확정값
- 폰트: **Pretendard Variable** (fallback: Pretendard → 시스템 → `Noto Sans KR` → sans-serif). 별도 디스플레이 폰트 도입하지 않음.
- 스케일(§3 표)과 **궁합 % 숫자 스타일**: `font-weight 800 / tabular-nums / % 기호는 숫자의 0.5em·weight 600 / 색은 accent(다크 accent-400)` — C2가 `stat-number` 컴포넌트 토큰으로 고정.

### D-6. 보이스&톤
- 존댓말 수위: **해요체 고정** (하십시오체·반말 금지, 법적 고지만 "-합니다"체 허용).
- 이모지: 시스템 UI 문구 0개, 축하·게임 결과 등 감정 피크 1개 이하 (§4.3 규칙).
- 죄책감·재촉·조바심 카피 전면 금지(A3·A4 금지 목록과 동일 효력). 상황별 카피는 §4.2 표가 기준 문안.

### D-7. 로고
- Phase 1은 **워드마크(텍스트 로고) + 말풍선-오리 하이브리드 심볼(§5)** 방향만 확정, 실제 벡터 제작은 C2 이후 별도 작업. 서비스명 미확정이므로 심볼은 이름과 독립적으로 성립하는 형태(말풍선+물결)를 우선한다.

## 1. 서비스명

### 1.1 확정: 가칭 "덕메이트(DuckMate)" 유지

- "덕질(덕후) + 메이트"의 직관적 합성 + 영문 표기 시 Duck(오리)으로 읽히는 이중성 → 마스코트화 여지.
- PRD 오픈 이슈 #1에 따라 **최종 확정은 소유자 몫**. 스토어 제출(Phase 4) 전까지 결정하면 되고, 그때까지 모든 산출물은 "덕메이트"를 사용하되 브랜드명은 코드에서 단일 상수로 관리한다.
- 리스크: "덕"이 데이팅 문맥에서 다소 가벼움 / 국내 상표 데이터베이스(KIPRIS) 제45류(교제 알선)·제42류(SW) **검색 필요 ⚠️**.

## 2. 컬러 시스템

### 2.1 방향 확정

스펙 C1 정의("활기 있되 유치하지 않게: 딥 바이올렛 + 코랄 액센트 + 오프화이트")를 그대로 확정한다. `apps/web/app/globals.css`의 임시 토큰은 이 방향과 일치하므로 **폐기하지 않고 확정·확장**한다(기존 7단계 brand + 3단계 accent + surface/ink 전부 유지, 값 변경 없음).

- **딥 바이올렛(brand)** = 취향·덕질의 세계관, 밤(P4의 주 활동 시간대), 몰입. 데이팅 앱 클리셰(핑크/레드 일변)와의 차별.
- **코랄(accent)** = 심장 뛰는 순간에만 쓰는 감정색. 궁합 %, 좋아요, 매칭 리빌, 스트릭 불꽃. **화면당 코랄 사용 영역은 1~2곳으로 제한**해 희소성을 유지한다(C2 컴포넌트 규칙으로 집행).
- **오프화이트(surface)** = 차갑지 않은 종이 질감. 순백 `#ffffff`는 카드(`surface-raised`) 전용으로 분리해 위계를 만든다.

### 2.2 전체 스케일 (50~900)

hex는 상단 **D-2 표가 유일한 원본**이다. 생성 논리: 기존 확정값(brand 50/100/300/500/600/700/900, accent 400/500/600)을 앵커로 두고 사이 단계를 지각적 균등 보간, 시맨틱 3색(success/warning/danger)은 brand·accent와 채도 온도를 맞춰 생성했다.

용도 규약:
- **50~100** 배경 틴트(선택된 칩, 알림 배지 배경) · **200~300** 보더·다크모드 텍스트 · **400~500** 그래픽·게이지·대형 숫자 · **600~700** 라이트 모드 텍스트·버튼 배경 · **800~900** 딥 배경(스플래시, 매칭 리빌 배경)·다크모드 `primary-fg`.

다크모드는 "검정"이 아니라 **바이올렛이 스며든 밤하늘**로 정의한다 (P4 페르소나의 밤 11시~새벽 1시 사용 맥락이 핵심 사용 씬).

### 3.1 폰트

- 자간: 한글 UI 기본 `letter-spacing: -0.01em`, display급은 `-0.02em`.

| `caption` | 13px / 18px | 500 | 타임스탬프, 라벨, 법적 고지(**자동갱신 고지 최소 13px** — PRD §4 준수, 이보다 작은 단계 없음) |

### 3.3 숫자 강조 — 궁합 % 스타일 (`stat-number`)

궁합 %는 브랜드의 시그니처 순간이므로 전용 스타일을 고정한다.

- **크기**: 히어로(궁합 카드·리빌) 56px/1.0, 인라인(리스트·게이지 옆) 22px/1.0
- **weight 800, `font-feature-settings: "tnum"` (tabular-nums)** — 카운트업 애니메이션 시 폭 흔들림 방지
- **% 기호**: 숫자 대비 0.5em, weight 600, 숫자와 0.05em 간격 — 숫자가 주인공
- **색**: 라이트 `accent-500`(56px 대형이므로 3:1 충족·§2.4), 인라인 22px 미만이면 `accent-700`. 다크는 모두 `accent-400`
- 숫자 옆 "이유 3줄"(설명 가능한 매칭)은 `body-sm`/`ink-muted` — 숫자는 뜨겁게, 근거는 차분하게
- **고지 문구 동반 필수**: 궁합 %가 노출되는 모든 화면에 caption으로 "궁합은 재미와 추천용이에요" (AdSense/품질 정책의 "재미용" 고지 원칙 및 A2 §4 설계 규칙 승계)

## 4. 보이스 & 톤

### 4.1 핵심 원칙 5

1. **덕질을 존중한다 — 절대 번역하지 않는다.** "그런 거 좋아하세요?"의 세계에서 온 유저(P1)에게 최애·입덕·잡덕 같은 팬덤 어휘를 따옴표 없이 쓴다. 단, 특정 팬덤 내부 은어(계정 용어 등)는 P2가 소외되므로 금지.
2. **어색함을 대신 깨준다.** 서비스가 먼저 말 걸고, 먼저 제안하고, 먼저 핑계를 만들어준다. 유저에게 "대화를 시작해보세요" 같은 숙제를 던지는 카피 금지 — 항상 구체적 행동 1개를 들고 간다.
3. **죄책감·조바심을 팔지 않는다.** 스트릭이 끊겨도, 답장이 늦어도, 결제를 안 해도 유저 잘못이 아니다. "놓치면 사라져요"류 카피는 컴포넌트 자체가 존재하지 않는다(A4 다크패턴 금지 10항 집행).
4. **안전은 단호하고 건조하게.** 평소의 다정함과 분리해, 신고·제재·마스킹 안내는 이모지 없이 짧고 명확하게. 안전 기능 앞에서 귀여운 척은 신뢰를 깎는다.
5. **재지 않고, 판정하지 않는다.** 궁합은 "재미와 추천용"이고 외모·매력 점수는 존재하지 않는다. 유저를 평가하는 화법("당신의 매력 점수") 전면 금지 — 항상 "둘 사이"를 말한다("두 분의 취향이 겹쳐요").

### 4.3 이모지 규칙

- **시스템 UI 문구(버튼·라벨·에러·설정): 0개.**
- **감정 피크 순간(매칭 리빌·스트릭 달성·퀘스트 완료): 최대 1개**, 문장 끝에만. 허용 팔레트: 🎉 🎊 ✨ 🔥 🐤 (오리 모티프는 🐤로 통일, 🦆는 사실적이라 톤 불일치).
- **금지**: 안전/신고/제재/결제/법적 문맥 전체, 눈물·애원 계열(😢 😭 🙏 — 죄책감 유도), 하트 계열 남발(❤️는 '좋아요' 아이콘이 이미 담당).
- 푸시 알림 제목에는 0개, 본문에 최대 1개 (D7 카피 원칙에 병합).

### 4.4 존댓말 수위

- **해요체 고정** ("~해요/~예요/~할게요"). 하십시오체는 딱딱하고(20~34세 타겟), 반말은 데이팅 문맥에서 무례 리스크.
- 예외: 법적 고지·약관·환불 안내는 "-합니다"체 허용 (B2 문서와 톤 일치).
- 물결표(~), "님아", 과장 감탄사("헐", "대박") 금지 — 친근함은 어휘가 아니라 '먼저 제안하는 행동'으로 표현한다(원칙 2).
- 유저 지칭: 기본 "회원님" 대신 **닉네임 직접 호명**을 우선, 불가한 문맥에서만 "회원님".

## 5. 로고 / 심볼 방향성 (텍스트 스펙 — 벡터 제작은 후속 작업)

### 5.1 오리 모티프 — **조건부 채택 제안**

- **채택 논리**: DuckMate의 오리는 ① 위협적이지 않고(데이팅 앱 진입 장벽 완화, P2·P4) ② "물 위는 평온, 물밑은 열심히 발질" = 겉은 시크해도 속은 열정인 덕후 서사와 정확히 겹친다 ③ 🐤 이모지·스티커·마스코트 전개가 쉽다.
- **경계 조건**: 서비스명이 대안으로 바뀌면(§1.2) 오리 서사가 약해질 수 있다("퐁당"은 유지 가능, "겹"·"덕분에"는 무관). 따라서 심볼은 **오리에 의존하지 않고도 성립하는 형태**를 1안으로 한다.

### 5.2 심볼 1안 (권장): "말풍선 + 물결" 하이브리드

- 둥근 말풍선 실루엣의 하단 꼬리를 물결 한 줄로 변형 — 보는 사람에 따라 "말풍선(대화)"로도, "물에 뜬 오리 몸통(덕)"으로도 읽히는 중의적 형태. 이름이 어느 안으로 확정돼도 생존한다.
- 컬러: 심볼 바탕 brand-600, 내부 포인트(물결 또는 부리 한 점) accent-500. 단색 버전은 brand-600 1도.
- 앱 아이콘: brand-600→brand-800 수직 그라데이션 배경 + 심볼 백색 리버스. 오프화이트 배경 버전 병행.

### 5.3 워드마크

- Pretendard Variable weight 800, 자간 -0.02em의 커스텀 워드마크 "덕메이트". 별도 레터링 발주 없이 Phase 1~3 사용 가능.
- 최소 사용 규격: 심볼 단독 24px, 심볼+워드마크 조합 가로 96px 이상. 그 미만에서는 심볼만.

### 5.4 금지 사항

- 사실적 오리 일러스트(🦆류), 하트로 변형된 오리(데이팅 클리셰), 심볼에 3색 이상 사용, 코랄 배경 위 백색 심볼(대비 FAIL — §2.4).

## 6. C2에게 — 구현 인수인계 체크리스트

1. `globals.css` `@theme`에 D-2 표의 누락 단계(brand-200/400/800, accent-50~300/700~900, success/warning/danger 전 단계)와 D-3 시맨틱 토큰을 추가 — 기존 값은 1개도 수정하지 말 것.
2. 다크모드는 `prefers-color-scheme` + 수동 토글 겸용, 토큰 스왑 방식(D-3 표의 라이트→다크 매핑 그대로).
3. `stat-number`(§3.3), 코랄+백색 조합 금지 린트(D-4), 거절 버튼 70% 규칙을 컴포넌트 레벨에서 강제.
4. 카운트다운·재고·죄책감 카피 컴포넌트는 **만들지 않는다** (PRD 공통 확정 5항).
5. 브랜드명 문자열 상수화(D-1) — 카피 내 "덕메이트" 하드코딩 금지.
