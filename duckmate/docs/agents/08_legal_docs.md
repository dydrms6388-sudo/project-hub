## 다음 에이전트에게 넘기는 결정사항

### E4 (법적 페이지 렌더링·변수 치환)
1. **원본 형식은 `.md`(frontmatter 포함)**, 경로 `apps/web/content/legal/<slug>.md`. PRD §0-21의 `.mdx`는 `.md`로 확정 — 문서에 JSX가 없고 company 정적 export에서 같은 파일을 쓰기 쉽다.
2. **변수 단일 소스 = `apps/web/config/company.ts`** (PRD §7의 `apps/company/config/company.ts`를 이 경로로 통일, company 앱은 import). 키는 README 표의 18개 `UPPER_SNAKE`이며 `{{KEY}}` → `company[KEY]` 문자열 치환. 빈 값은 `{{KEY}}`를 그대로 노출 + 빌드 경고(`scripts/check-legal-placeholders.mjs`). `COMPANY_NAME`·`ECOMMERCE_REG_NUMBER` 비면 `PAYMENTS_ENABLED` 강제 false.
3. PRD §0-27의 `{{BIZ_NO}}`·`{{ECOM_NO}}`·`{{PRIVACY_OFFICER}}`는 `BUSINESS_NUMBER`·`ECOMMERCE_REG_NUMBER`·`PRIVACY_OFFICER_NAME`으로 대체. 체크 스크립트는 README 표에 없는 키를 경고한다.
4. 라우트: `/legal/terms`, `/legal/privacy`, `/legal/location`, `/legal/youth-policy`(PRD의 `/legal/youth`는 redirect 별칭), `/legal/community-guidelines`, `/legal/refund-policy`, `/legal/business`(마크다운 없음, `company.ts` 직접 렌더). 전부 `(public)` 그룹, 인덱싱 허용, 푸터 1탭.
5. 페이지 하단에 frontmatter의 `version`·`effective_date` 표기. `effective_date > 오늘`이면 "개정 예정" 배지 + 현행 버전 링크(`.next.md` 규칙, README 참조).
6. 결제 화면(Phase 3): 결제 버튼 **위**에 "매월 {일}에 ₩{금액} 자동 결제 · 언제든 해지" 고정 문구 + 환불정책 링크 + "디지털콘텐츠는 제공 개시된 부분의 청약철회가 제한되며 사용분을 차감합니다" 1줄 — 약관 제18조 제2항·환불정책 §2가 "결제 화면에 표시한다"고 약속하므로 **문서와 UI가 함께 있어야 법적 효력**이 생긴다. 부스트 발동 확인 화면에도 "발동하면 환불되지 않아요" 표시.

### D1 (consents 테이블)
7. `profiles.consented_at` 단일 컬럼(PRD §3.1)만으로는 **문서별 버전 재동의**를 판단할 수 없다. `consents(user_id, doc_slug, version, consented_at, method)` 테이블 추가를 권고. PK `(user_id, doc_slug, version)`. `method ∈ {'signup','reconsent','settings'}`. `profiles.consented_at`은 최신 동의 시각 캐시로 유지.
8. 가입 시 필수 동의 3건: `terms`, `privacy`, `youth-policy`(개별 체크 3 + 전체 동의 1). `location`·`community-guidelines`·`refund-policy`는 게시만(동의 행 없음).
9. **재동의 판정 규칙 = MAJOR 버전 비교**: 로그인 시 `consent_required` 문서마다 `major(consents.version) < major(현재 frontmatter.version)`이면 재동의 화면. MINOR/PATCH는 재동의 없음. 문서 편집자는 이 규칙 때문에 불리한 변경을 반드시 MAJOR로 올린다(README 표).
10. 재동의 화면은 서비스 진입을 막되(추천·채팅 전 1회), 탈퇴 경로를 같은 화면에 노출한다(약관 제3조 제5항 — 미동의 시 해지 가능 + 잔여 유료분 환불).
11. 위치정보 약관은 `consent_required: false`. GPS 수집 기능이 생기면 `location`을 2.0.0으로 올리고 `consent_required: true` + 별도 동의 체크(위치정보법 제19조)로 승격.

### E5 (company 사이트 법적 고지 페이지·설정 화면)
12. company 법적 고지 페이지는 web과 **같은 6개 파일 + `/legal/business`** 를 렌더. "안전과 신뢰" 페이지의 공개 약속 문구는 "신고 접수 후 24시간 내 1차 조치"로만(A5 §6, P3는 접수 확인 통보로 충족).
13. 설정 화면 링크 목록: 이용약관 / 개인정보처리방침 / 위치정보 이용약관 / 청소년보호정책 / 커뮤니티 가이드라인 / 환불정책(Phase 3 전에는 숨김 가능) / 사업자 정보. 탈퇴 화면에 "탈퇴 전 환불 신청 필요" 안내(약관 제9조 제6항). 개인정보 다운로드는 Phase 1 문의 폼 → 10일 내 이메일 JSON(개인정보처리방침 제7조).
14. 첫 매칭 안전 모달·오프라인 만남 배너의 "전체 보기" 링크는 `/legal/community-guidelines#4-안전-팁`.

### D5/D8 (문서가 약속한 운영 수치 — 코드 상수와 일치 필수)
15. 신고 24h 1차 조치 / 미성년 P0 1h 목표 / 이의신청 7일·1회·72h 답변 / 증거 보존 90·180일·영구정지 5년·legal_hold / 탈퇴 7일 유예 / CI 해시 1년(영구정지 5년) / 접속 로그 3개월 / 결제 5년 / 휴대폰 해시 30일 / age_blocked 30일 삭제. 이 값들이 코드에서 바뀌면 개인정보처리방침 MAJOR bump가 필요하므로 상수 변경 PR에 문서 변경을 같이 넣는다.
