## 다음 에이전트에게 넘기는 결정사항

### 판정 (법 적용 여부)
1. **위치정보법 미적용 — 위치기반서비스사업 신고 불필요(판정)**. 근거: 위치정보 정의(법 §2 1호)는 "전기통신설비를 이용하여 수집된" 장소 정보. 사용자가 직접 고른 `region_code`(시/군/구)는 주소와 같은 **일반 개인정보**이며 방통위 해설·실무 의견도 동일. 조건: (a) 브라우저 Geolocation API·네이티브 위치 권한을 **어디서도 호출하지 않음**, (b) IP→지역 변환을 추천·기본값·분석 어디에도 쓰지 않음, (c) Capacitor 앱 매니페스트에 위치 권한 미선언. 셋 중 하나라도 깨지면 신고 대상으로 전환(소상공인은 개시 후 1개월 내 신고). `(변호사 검토)` 의견서 1장으로 확정.
2. **`/legal/location` 페이지는 유지하되 성격을 "위치정보 미수집 고지"로 변경**. 브리프 규칙 4는 페이지 게시를 요구하므로 삭제하지 않는다. 제목 "위치정보 이용 안내", 본문 = ①GPS·IP 위치 미수집 선언 ②`region_code` 수집 목적·보유기간 ③변경 시 고지. 위치정보 **동의 체크는 만들지 않는다**(수집이 없으므로 동의 대상이 없음). PRD §4.7의 `location` 동의 키 삭제.
3. **결혼중개업법 미적용(판정)**. 근거: 동법 §2는 "결혼을 위한 상담·알선"을 업으로 하는 경우. 덕메이트는 취미 친구/데이팅 매칭이며 결혼 목적 상담·알선·수수료가 없다. 단 2026-02 결혼정보회사 운영 데이팅앱 영업정지 사례가 있으므로 **금지어 규칙**: 서비스명·카피·스토어 설명·광고에 "결혼", "배우자", "혼인", "결혼정보" 사용 금지. `scripts/check-copy.mjs`(E5)에 grep 항목 추가. `(변호사 검토)`
4. **청소년유해매체물 아님(자기 판정, 확인 필요)**. 여가부 랜덤채팅앱 고시(2020-12 시행)는 "실명·휴대전화 인증, 대화 저장, 신고 기능" 없는 불특정 대화 서비스를 지정. 덕메이트는 3요건을 모두 갖추고 프로필 기반 매칭이므로 고시 대상이 아니다. **그러나 자체 정책상 만 19세 전용**이므로 연령확인 의무는 청소년보호법이 아니라 약관·스토어 등급(19+)에서 발생. 유해매체물로 판정될 경우에만 "회원 연령확인 1년 갱신"(시행령) 의무 → `identity_verifications.verified_at` 기준 1년 재인증 플래그를 **예약 컬럼**(`reverify_due_at`, Phase 1 미사용)으로만 둔다.
5. **연령확인 = 자기신고(생년월일)만으로는 부족, 본인인증(L2)이 성인 콘텐츠 노출 전제**. PRD §0-1·2와 일치. L0/L1(미인증)은 타인 프로필·채팅·사진 어느 것도 볼 수 없어야 하며 이것이 "성인 전용" 주장의 유일한 법적 근거다. Phase 1 초대제 베타(allowlist)는 성인 확인이 안 된 일반 가입자가 L2가 될 수 없으므로 문제없음. 공개 런칭은 실인증(Phase 4) 이후 — 변경 불가.
6. **청소년보호책임자: 법정 지정 기준 미달이지만 런칭 시 자율 지정·게시**. 정보통신망법 §42조의3·시행령 §25: 일평균 이용자 10만 명 이상 또는 정보통신서비스 매출 10억 원 이상(`확인 필요`: 유해매체물 제공자 요건과의 결합 조건). 성인 전용 서비스 신뢰 표시로 `/legal/youth` 하단에 책임자 성명·직위·연락처 표기(`{{YOUTH_OFFICER}}` 플레이스홀더).
7. **전기통신사업법 부가통신사업 신고: 자본금 1억 원 이하는 신고 면제(신고한 것으로 간주)**. 법인 설립 시 자본금 1억 초과면 과기정통부 신고 필요. `(확인 필요)` 소유자 법인 자본금 확인.
8. **불법촬영물 유통방지 의무(전기통신사업법 §22조의5)**: 일평균 이용자 10만/매출 10억 이상 부가통신사업자 대상. 현재 미달이나 채팅 이미지 기능이 있으므로 A5 §8 `held`·신고 파이프라인을 그 준비로 본다. 기준 도달 시 방심위 표준 DNA 필터링 도입(Phase 4 이후 재검토).
9. **개인정보 국외이전 없음(판정, 조건부)**. Supabase 리전 **ap-northeast-2(서울) 고정**(PRD §5.5), Toss·포트원 국내. 조건: (a) Vercel 서버리스/Edge 함수 리전 `icn1` 고정 — `vercel.json` `regions: ["icn1"]`, (b) Supabase Storage·백업도 동일 리전, (c) Vercel Analytics는 IP 기반 국가 집계를 미국에서 처리하므로 **처리방침 "국외이전" 항목에 예비 기재**(항목: 접속 로그·기기 정보, 목적: 서비스 분석, 국가: 미국, 수탁자: Vercel Inc.). Web Push 엔드포인트(Google FCM/Apple)는 푸시 본문에 개인정보를 넣지 않으므로 "전송을 위한 필수 처리"로 고지만. `(변호사 검토)`
10. **개인정보 자동화 결정(개인정보보호법 §37조의2, 2024-03 시행)**: 자동 제재(경고·채팅 제한 24h)는 정보주체 권리에 영향을 주는 자동화 결정에 해당할 수 있음 → 처리방침에 "자동화된 결정 기준·절차" 항목 추가, 이의신청(A5 §4.5)을 "설명 요구·거부권 행사 창구"로 명시. 추천 알고리즘은 "중대한 영향" 아님으로 판정하되 점수 요소(§0-40)를 처리방침에 개요 수준으로 기재. `(변호사 검토)`

### D1 스키마 요청
11. **`consents` 테이블 신설**: `id, user_id, key(enum consent_key), version(text, 문서 버전), agreed(bool), agreed_at, withdrawn_at, ip_hash(sha256+salt), ua_hash, source(enum: onboarding/settings/checkout/banner)`. 유니크 없음(이력 보존), 최신 행이 현재 상태. RLS: 본인 insert/select, update 금지(철회는 새 행). PRD §3.1의 `profiles.consented_at`은 **삭제**(consents로 대체).
12. **`legal_documents` 테이블**: `key(terms/privacy/location/youth/business/refund/marketing), version, effective_at, content_hash, requires_reconsent(bool)`. mdx 커밋 시 시드 갱신. `requires_reconsent=true` 버전이 있고 사용자의 최신 `consents.version`이 그보다 낮으면 홈 진입 시 재동의 모달(E5).
13. **`push_subscriptions`에 `kind_allowed(jsonb)` 대신 consents 참조**: 마케팅 푸시 발송 배치는 `consents(key='marketing_push', agreed=true, withdrawn_at is null)`만 대상. 서비스 알림(추천 도착·매칭·답장·검수 결과)은 동의 불요.
14. **`age_blocked` 상태의 데이터 최소화**: `profiles.birth_date`·닉네임은 저장하지 않고 `phone_hash` + `age_blocked_at`만 30일 보관(재시도 차단용). 현재 A5 §2.1 "계정 생성하되 age_blocked"는 미성년자의 생년월일을 30일 보관하게 되므로 수정.
15. **탈퇴 시 삭제 대상에 `consents.user_id` 가명화 추가**: 삭제하지 않고 `user_id`→`ci_hash` 또는 무작위 대체키로 치환, 5년 보관(전자상거래 계약 기록·분쟁 대응). 결제 동의(`auto_renew`)는 반드시 남아야 함.
16. **`inquiries`·`refund_requests`는 3년 보관**(전자상거래법 시행령 §6 소비자 불만·분쟁 3년) — A5 §11.1에 없는 항목, 추가.
17. **`skus`·가격 표시 이력 6개월 보관**(표시·광고 기록 6개월): `skus`는 삭제 대신 `retired_at`로 비활성화, 가격 변경은 `sku_price_history` 행 추가(D6, Phase 3 파일만).

### E4/E5 화면 요청
18. **가입 동의 화면(S2 직후) 체크 항목 5개 개별 + 전체 동의 1개**: `age_19`·`terms`·`privacy`·`evidence_snapshot`(필수 4) + `marketing_push`(선택). 필수 항목은 **사전 체크 금지**(다크패턴 "특정 옵션 사전선택" 금지). 각 항목 옆 "보기" 링크로 전문 열람 가능해야 하며, 약관규제법 §3 설명의무를 위해 `terms`·`evidence_snapshot`의 핵심 3줄(성인 전용·제재 시 환불 없음·신고 시 대화 보관)을 체크박스 아래 **요약 문구로 노출**.
19. **결제 화면(Phase 3) 고정 요소**: ①사업자 정보 블록(§2.1 표시 항목 9개) ②"매월 자동 갱신, 언제든 해지" 문구를 **결제 버튼 바로 위**에 ③`auto_renew` 체크(사전 선택 금지, 미체크 시 버튼 비활성) ④소모성 아이템은 `digital_no_withdrawal` 체크("사용 시작 후 청약철회 불가") ⑤청약철회·환불 규정 링크. `{{COMPANY_NAME}}`·`{{ECOM_NO}}` 미입력 시 `PAYMENTS_ENABLED=false` 강제(PRD §0-27 유지).
20. **설정 > 알림 화면**: 마케팅 수신 토글 옆에 "동의일 YYYY-MM-DD"와 "수신 동의는 2년마다 확인해요" 표기. 서비스 알림 슬롯 on/off와 **별도 섹션**.
21. **설정 > 계정 화면**: 개인정보 열람·정정·삭제·처리정지·전송(다운로드) 5개 권리 진입점을 한 곳에(Phase 1은 문의 폼 프리필 링크, Phase 4 자동화). 탈퇴는 "7일 뒤 삭제돼요 · 지금 바로 삭제" 두 옵션 제공(§5 판정 참조).
22. **푸터 공통(web·company)**: 상호·대표·사업자번호·통신판매업 신고번호·주소·이메일·개인정보보호책임자·청소년보호책임자·호스팅 제공자(Vercel Inc.) + `/legal/*` 5종 링크. 값 없으면 `[TODO_사업자정보]`가 그대로 보이고 `check-legal-placeholders.mjs` 경고.

### B2·E6·소유자
26. **법적 페이지 6종으로 확정**: PRD 5종 + `/legal/refund`(청약철회·환불·구독 해지 규정, Phase 3 전 게시). `/legal/business`는 사업자 정보 + 통신판매업 신고 + 호스팅 사업자 표시 전용.
27. **약관 변경 고지 규칙**: 일반 변경 7일 전, 불리한 변경 30일 전 공지(전자상거래 소비자보호 지침) + `requires_reconsent`면 재동의 모달. 공지 위치 = 홈 상단 배너 + `/legal/*` 페이지 상단 "개정 예고" 블록 + 시행일 병기.
28. **개인정보보호책임자 = 대표자(소유자 1인)** 가능(시행령 §32, 소규모 사업자 특례). 성명·연락처를 `company.ts`의 `privacyOfficer`에 입력 → 처리방침·푸터에 자동 반영.
29. **현금영수증**: 통신판매업은 의무발행업종이므로 건당 10만 원 이상 현금성 결제 시 요구 없어도 발급. Toss 카드·간편결제는 해당 없음, 계좌이체·가상계좌를 열면 Toss 현금영수증 자동발급 옵션 필수. Phase 3 결제수단을 **카드·간편결제로 한정**하면 실무 부담 0.
30. **런칭 순서(§7)**: 사업자등록 → (법인이면 자본금 확인) → PG 사전가입·구매안전서비스 이용확인증 → 통신판매업 신고 → 포트원·Toss 본계약 → CPO·청소년보호책임자 지정·게시 → 처리방침 시행일 확정. 결제 오픈 전 ≈ 3~5주.

- **민감정보(법 §23)·고유식별정보(§24)·생체정보 미수집 선언**: 주민번호·여권·운전면허 없음. CI는 고유식별정보가 아니나 "제2의 주민번호" 논란이 있으므로 원문 미저장, `sha256(CI+IDENTITY_CI_SALT)`만(PRD §0-39 유지). 얼굴 검사 어댑터는 `face_count`·`confidence`만 반환하고 **특징점(임베딩)을 저장하지 않는다** — 저장하면 생체정보 처리가 되어 별도 동의 필요. D7 인터페이스에 임베딩 반환 필드 금지 명시.

## 7. 약관규제법
- 명시·설명의무(§3): 약관 전문 링크 + 중요 조항 요약 노출(§0-18). 동의 화면 스크린샷을 E2E 아티팩트로 보관.
- 불공정 조항 회피: "위반 정지 시 환불 없음"은 **위반 사실이 확정(제재 level≥3 confirmed)된 경우로 한정**하고 잔여 기간 비례 환불 불가 근거를 약관에 명시 `(변호사 검토)`. 사업자 면책 포괄 조항·손해배상 상한 일방 규정 금지. 관할 법원 조항은 소비자 주소지 기준.
- 변경 고지: 7일/30일 규칙(§0-27). `legal_documents.effective_at`이 도래하기 전 공지 기간 검사 스크립트(`check-legal-effective.mjs`, 경고만).

## 8. 전자금융·결제 · 세금
- PG(Toss) 이용 시 사업자는 전자금융업 등록 불요(PG가 등록업자). 사업자 의무: 결제 화면 표시(§1), 결제 취소·환불을 PG API로 처리(현금 환불 금지), 결제 정보(카드번호) 서버 미저장 — `payments`는 `provider_payment_key`만.
- 현금영수증: §0-29. 결제수단 카드·간편결제 한정 권고.
- 부가세: 구독·아이템은 과세 용역, 표시가 부가세 포함. 개인 소비자 대상이므로 세금계산서 발행 불요, 카드매출은 자동 신고 자료. 법인 고객 없음. 간이과세자는 세금계산서 발행 불가·통신판매업 면제 대상이지만 구독 매출로 곧 일반과세 전환 → 처음부터 일반과세 권고 `(세무사 확인)`.
- 앱 마켓 결제(IAP·수수료·가격 차이 고지)는 **B3 문서** 참조.
