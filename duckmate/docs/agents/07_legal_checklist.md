## 2. 통신판매업 신고

**① 요건.** 유료 구독·아이템 판매 = 통신판매업(전자상거래법 §12). 관할 시·군·구청(정부24)에 신고 후 신고번호를 §1 표에 표시. (직전년도 거래 횟수 50회 미만 등 면제 특례가 있으나, 구독 서비스는 즉시 초과하므로 **면제에 기대지 않고 결제 오픈 전 신고 완료**로 확정. 구매안전서비스 이용확인증(에스크로/PG) 필요 — Toss Payments 계약 시 발급.)

**② 시점.** **Phase 3 결제 오픈 전 하드 블로커** (PRD 오픈 이슈 #3 확정사항). 신고 자체는 사업자등록 직후 미리 해두는 것을 권장.

**③ 코드 지시.**
- **D6**: 결제 세션 생성 Edge Function 최상단에서 `company.ts`(또는 env `ECOMMERCE_REG_NO`)의 통신판매업 신고번호 존재를 검사 — 없으면 503 + "결제 준비 중" 응답. 웹훅 핸들러는 무관(기존 구독 정산은 항상 동작).
- **E4**: 페이월·구독 관리 화면에서 같은 값을 검사해 결제 CTA를 비활성화하고 안내 문구 표시(서버 검증 D6이 최종 방어선, UI는 UX용).
- **G3 연동 노트**: Phase 3 게이트 체크리스트에 "통신판매업 신고번호 입력 확인" 항목 추가(PRD 오픈 이슈 #3).

## 3. 위치정보법 — 위치기반서비스사업 신고 필요 여부 판정

**① 요건·판정.** 위치정보법상 "위치정보"는 전기통신설비·측위 수단으로 **수집된** 장소 정보(§2①1). 덕메이트는:
- 이용자가 온보딩에서 **직접 선택**하는 `region_code`(행정구역 단위)만 저장,
- GPS·기지국·Wi-Fi 측위, IP 기반 위치 추정, 실시간 위치 노출 **전부 미사용** (스펙 §1 "하지 않는 것" + PRD F-DIS-10 Won't).

→ 자기신고 행정구역은 위치정보법상 위치정보에 해당하지 않으므로 **위치기반서비스사업 신고(§9의2) 불요** 판정(L1). 다만 스펙 §0-4가 요구하는 "위치정보 이용약관" 페이지는 유지하되, 내용을 "현재 정밀 위치정보를 수집하지 않으며 이용자가 입력한 행정구역 정보만 이용" 고지로 작성한다(B2).

**정밀 위치를 도입하는 순간 필요해지는 절차** (예: "내 주변 이벤트", 거리 기반 추천):
1. 방송통신위원회에 **위치기반서비스사업 신고**(§9의2) — **서비스 개시 전** 완료.
2. 위치정보 이용약관을 법정 기재사항으로 개정 + 개인위치정보 수집·이용·제공 **별도 동의**(§18·§19, 개인정보 동의와 분리).
3. 위치정보관리책임자 지정, 수집사실 확인자료 보존, 즉시 수집 중지(동의 철회) 수단, 8세 이하 보호의무자 동의 체계.

**② 시점.** 판정·약관 고지 = **Phase 1**. 신고 절차 = 정밀 위치 기능 도입 시(현 로드맵에 없음).

**③ 코드 지시.**
- **D1**: `profiles.region_code`는 행정구역 코드 테이블(시·군·구 수준) FK 또는 CHECK로 제한 — 위경도·상세주소 컬럼을 만들지 않는다. 스키마 주석에 "위치정보법 신고 불요 판정의 전제 — 정밀 위치 컬럼 추가 = B1 재판정 필요" 명시.
- **D3, E2**: 매칭·탐색에서 `region_code` 일치/인접 비교만 사용. `navigator.geolocation` 호출 코드 작성 금지 — **E6**의 검증 스크립트에 `geolocation|watchPosition|getCurrentPosition` grep 가드 추가(히트 시 빌드 경고 + B1 재판정 플래그).
- **E1**: 온보딩 지역 선택은 드롭다운/검색 선택 UI로만("현재 위치로 찾기" 버튼 금지).
- **B2**: 위치정보 이용약관을 위 고지형으로 작성, 정밀 위치 도입 시 교체할 조항 초안을 주석으로 동봉.

## 8. 본인확인·연령 확인 — PASS의 법적 지위

**① 요건.**
- 주민등록번호는 법령 근거 없이 처리 금지(개인정보보호법 §24의2) → 대체수단인 **본인확인기관**(정보통신망법 §23의3, 방통위 지정: 통신3사 PASS·아이핀 등)의 CI/DI를 사용한다. 포트원은 본인확인기관이 아니라 **연동 대행(게이트웨이)** — 법적 본인확인 효력은 뒤단의 PASS/다날(본인확인기관)에서 나온다. 따라서 포트원 계약 시 본인확인서비스 이용약관 및 뒤단 기관 확인 필요.
- 성인 확인: 법정 성인인증(청소년유해매체물 제공 시의 연령·본인확인 의무) 수준의 확실성을 확보하려면 자기신고가 아닌 **본인확인기관의 생년월일 검증**이 필요 — 덕메이트의 Lv2 PASS 재검증(A5 §1.3 게이트 2)이 이를 충족. Phase 1~3의 스텁 기간에는 법정 수준 성인 확인이 아직 없는 상태이므로, **미인증(Lv0~1) 상태의 노출·접촉 면적 0 원칙(런타임 게이트)이 유일한 보완 장치**다.
- CI는 개인 식별 목적 외 이용 금지 — 저장은 1인 1계정·재가입 차단 목적의 **해시만**(A5 확정).

**② 시점.** 어댑터 인터페이스·3중 게이트 = **Phase 1**. 실키 연동 = **Phase 4** (PRD F-ONB-04).

**③ 코드 지시.**
- **D2**: (a) `IdentityVerifier` 어댑터 반환 타입에 `ci_hash`, `di`, `birth_date`, `provider`(pass/danal), `verified_at` 포함 — **CI 원문은 어댑터 경계에서 즉시 해시(salt 포함)하고 원문을 로그·DB 어디에도 남기지 않는다**. (b) PASS `birth_date`가 진실의 원천 — 자기신고값 덮어쓰기 + 이후 수정 불가(M1). (c) 만 19세 미달 시 즉시 banned+파기 큐(A5 게이트 2). (d) 스텁 구현에도 동일 인터페이스·동일 게이트 로직 적용(E2E가 실키 전환 시 무수정 통과하도록).
- **D1**: `blacklist(ci_hash, phone_hash, reason, created_at)` — service role 전용 RLS, 영구 보존(§4 파기 잡의 예외 대상으로 명시).
- **E1**: 인증 화면에 "본인확인은 방통위 지정 본인확인기관(PASS)을 통해 처리되며, 주민등록번호는 저장하지 않습니다" 고지 1줄.
- **G2 연동 노트**: 보안 리뷰 시 "CI 원문이 로그·에러 리포트·analytics에 유출되는 경로 없음"을 점검 항목에 추가.

**① 요건·판정.**
- **불법촬영물 등 유통 방지**(전기통신사업법 §22-5, "n번방법"): ⓐ 모든 부가통신사업자 — 방심위 등이 심의·요청한 불법촬영물 삭제·접속차단 의무. ⓑ **기술적·관리적 조치**(필터링, 표준 DNA DB 대조, 유통방지 책임자 지정, 연 투명성 보고) — **일평균 이용자 10만 명 이상 또는 매출 10억 원 이상** + 공개 게시판/SNS형 서비스 대상. **판정(L8): 덕메이트 Phase 1은 사적 1:1 대화만 있고 규모 미달 → ⓑ 비대상. ⓐ의 신고·삭제 대응 체계는 필요**하며 D5 설계(`CONTENT_ILLEGAL`=P0, evidence 보존, 24h SLA)로 이미 충족. **재판정 트리거 2개**: 공개 피드·게시판·그룹 채팅 도입 / 규모 요건 도달(§5-③ D8 경고와 연동).
- **로맨스 스캠**: 사업자에게 법정 신고 "의무"는 없으나, ⓐ 수사기관의 적법한 자료 요청 대응(A5 §4.4 절차 그대로 — 영장·법정 요청서 확인, audit_log, 창구=CPO), ⓑ 피해자 안내 의무는 자율 정책으로 확정: 경찰청 사이버범죄 신고(ecrm.police.go.kr)·금융감독원 1332 안내. 통신사기피해환급법상 지급정지는 피해자가 은행에 직접 요청하는 구조 — 앱은 **안내와 증거 보존**으로 협조.

**② 시점.** 신고·삭제 파이프라인, 안전 카드 안내 = **Phase 1** (F-SAF-01~06에 포함). 기술적 조치·투명성 보고 = **규모 도달 시**.

**③ 코드 지시.**
- **D5**: (a) `CONTENT_ILLEGAL` 신고는 기존 P0 파이프라인(1h 임시조치·즉시 스냅샷)에 더해 **해당 이미지의 채팅 노출을 즉시 차단**(수신자 화면에서도 숨김 — 유통 지속 방지, evidence 버킷 사본은 유지). (b) 방심위/수사기관의 삭제·차단 요청 처리용 어드민 액션 + 처리 내역 audit_log(향후 투명성 보고의 원천 데이터). (c) `SCAM_ROMANCE`/`SCAM_MONEY` 확정 건은 evidence를 종결+1년 보존(A5 §4.3 — 피해자의 수사 협조 요청 대비).
- **D4**: 이미지 전송 시 Storage 경로를 메시지 단위로 식별 가능하게(특정 이미지만 차단 가능한 구조 — 방 전체 차단 불필요). 기존 설계(비공개 버킷, 양측 Lv≥2) 유지.
- **D8**: 어드민에 "법적 요청 대응" 탭 — 수사기관 요청 접수 기록(요청 기관·근거 서류 유형·제공 범위·제공일), CPO만 접근. A5 §4.4의 "기간 경과 후 당사자 통지"를 위한 통지 예약 필드.
- **E3**: 스캠 안전 카드(F-SAF-06)에 신고 기관 안내 추가 — "금전 피해가 있다면: 경찰청 사이버범죄 신고 ecrm.police.go.kr · 금융감독원 1332" (수신자에게만 노출, A5 §5.2 원칙 유지).
- **E5**: 회사 사이트 안전 정책 페이지에 불법촬영물 신고 접수 채널(인앱 신고 + 이메일) 명시.
