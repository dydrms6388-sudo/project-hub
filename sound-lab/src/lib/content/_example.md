# 콘텐츠 파일 작성 규칙 (작성 에이전트용)

각 카테고리 파일은 `Record<string, SoundContent>`를 default export 한다.

```ts
import type { SoundContent } from "./types";

const content: Record<string, SoundContent> = {
  "shepard-tone": {
    intro:
      "계단을 오르는데 층수가 늘지 않는 그림을 소리로 옮기면 셰퍼드 음계가 된다. 아래 재생 버튼을 누르면 음이 계속 올라가는 것처럼 들리지만, 1분을 들어도 처음보다 높아져 있지 않다.",
    hear:
      "끝없이 상승(또는 하강)하는 음계가 들린다. 진행 속도 슬라이더를 음수로 내리면 방향이 뒤집히고, 옥타브 성분 수를 줄이면 순환의 이음매가 거칠어져 트릭이 드러나기 시작한다. 오래 들어도 음역이 실제로 이동하지 않는다는 점이 핵심이다.",
    signal:
      "실제 신호는 옥타브 간격(주파수비 2:1)으로 늘어선 사인 성분 여러 개다. 각 성분은 로그 주파수 축에서 종 모양 음량 창을 따라, 위로 갈수록 조용해지다가 창 밖에서 사라지고 아래에서 새 성분이 태어난다. 전체 스펙트럼의 무게중심은 한 자리에 고정되어 있다.",
    why:
      "음높이 지각은 절대 높이(height)와 옥타브 안 위치(chroma)의 두 차원으로 나뉜다. 옥타브 성분이 모두 함께 움직이면 chroma 변화만 남고 height 단서가 사라져, 청각계는 '방금 전보다 반음 올랐다'는 국소 판단을 계속 이어 붙인다. 국소 판단의 누적이 전역적으로 모순되어도 이를 감지할 별도 기제가 없어 착청이 유지된다. 성분 수가 적거나 재생 대역이 좁은 스피커에서는 경계 성분의 출입이 들려 효과가 약해진다.",
    history:
      "1964년 벨 연구소의 로저 셰퍼드가 컴퓨터 합성으로 처음 만들었고, 장클로드 리세가 이산 음계를 연속 활공으로 확장했다. 이후 무한 상승 긴장감을 위해 영화 음악(예: 크리스토퍼 놀런 작품들)에 널리 쓰이며 대중적으로 알려졌다.",
    sectionOrder: ["hear", "signal", "why", "history"],
    faq: [
      {
        q: "정말 무한히 올라가는 건가요?",
        a: "아니다. 스펙트럼의 무게중심은 고정되어 있고, 옥타브 안 위치(chroma)만 순환한다. 녹음해서 스펙트로그램을 보면 확인할 수 있다.",
      },
      {
        q: "어떤 조건에서 효과가 깨지나요?",
        a: "옥타브 성분 수를 3개까지 줄이거나 진행 속도를 아주 빠르게 하면 성분이 나타나고 사라지는 것이 들려 착청이 약해진다. 저역이 부족한 스피커에서도 효과가 줄어든다.",
      },
      {
        q: "하강도 되나요?",
        a: "된다. 진행 속도 슬라이더를 음수로 내리면 같은 원리로 끝없이 내려가는 음계가 만들어진다.",
      },
    ],
    presets: [
      { name: "표준 상승", values: [1, 5, 500] },
      { name: "빠른 하강", values: [-3, 6, 400] },
      { name: "성긴 3층 (트릭 관찰)", values: [1, 3, 500] },
    ],
    related: ["risset-rhythm", "tritone-paradox", "missing-fundamental"],
  },
};

export default content;
```

## 반드시 지킬 것

1. **intro/hear/signal/why/history 5개 필드 합계 1,000자 이상** (한국어 기준, 공백 포함).
2. **도입 문장(intro 첫 문장)의 구조를 항목마다 다르게** — 질문형, 상황 제시형, 역사적 사실형, 정의형, 비교형 등을 섞는다. 같은 파일 안에서 첫 문장이 같은 패턴으로 시작하면 안 된다.
3. **sectionOrder를 항목마다 다르게 섞는다** (4개 키의 순열 중 선택). 파일 안에서 최소 4가지 순서가 나오게 할 것.
4. **금지 표현**: "신기하죠", "놀랍게도", "놀라운", "신비", "믿기지 않" 등 감탄 유도 표현. 의료·진단·치료 효능 단정.
5. **근사와 한계 명시**: why에는 개인차, 재생 장비 의존성, 합성 방식의 근사 한계 중 해당되는 것을 반드시 언급.
6. **why는 확립된 청각 처리 지식만** — 추측 금지. principle 필드(JSON)의 근거를 풀어 쓴다.
7. **faq 정확히 3개, presets 정확히 3개.** preset values는 params 순서·개수와 일치, min~max 범위 안, step의 배수.
8. **related 정확히 3개** — 전체 40개 slug 중에서 원리가 이어지는 것을 고른다 (자기 자신 제외).
9. 문어체 평서문("~다")로 통일. 존댓말 금지 (FAQ 답변 포함).
10. presets 이름은 무엇이 들리는지 알 수 있게 짓는다.
