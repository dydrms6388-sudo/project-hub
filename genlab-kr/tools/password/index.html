비밀번호 생성기

암호학적 난수(crypto.getRandomValues)로 안전한 비밀번호를 만들고, 엔트로피 기반 강도까지 바로 확인하세요. 생성된 비밀번호는 화면에만 존재하며 어디에도 전송·저장되지 않습니다.

    비밀번호 생성기 소개

    이 비밀번호 생성기는 브라우저에 내장된 암호학적 난수 생성기 crypto.getRandomValues만 사용합니다. 일반적인 Math.random()은 예측 가능성이 있어 비밀번호 생성에 부적합하지만, 암호학적 난수는 운영체제의 엔트로피 소스를 사용하므로 예측이 사실상 불가능합니다. 생성 과정 전체가 방문자의 기기 안에서만 실행되며, 결과는 서버로 전송되거나 저장되지 않습니다.

    유사문자 제외 옵션을 켜면 0/O, 1/l/I, 5/S, 8/B처럼 눈으로 헷갈리기 쉬운 문자를 빼고 생성합니다. 손으로 옮겨 적어야 하는 와이파이 비밀번호나 초기 비밀번호를 만들 때 유용합니다. 선택한 문자 종류는 각각 최소 1자 이상 포함되도록 보정합니다.

    강도 산식 공개

    강도는 정보 엔트로피(bit)로 계산하며, 산식은 다음과 같습니다.

    E = L × log₂(N) − 감점
    L = 비밀번호 길이, N = 사용된 문자 종류의 문자 수 합(소문자 26 + 대문자 26 + 숫자 10 + 특수문자 27)

    감점(흔한 패턴 페널티):
    · 오름/내림차순 연속 문자열 3자 이상(abc, 321 등) — 1곳당 −8bit
    · 같은 문자 3회 이상 반복(aaa 등) — 1곳당 −8bit
    · 키보드 행 패턴 4자 이상(qwer, asdf 등) — 1곳당 −10bit
    · 흔한 비밀번호·약한 단어 포함(password, qwerty, dkssud 등 70개 목록) — 단어 길이 × 4bit(최대 −28bit), 가장 긴 일치 1건만

    등급: 28bit 미만 매우 약함 · 36bit 미만 약함 · 60bit 미만 보통 · 80bit 미만 강함 · 80bit 이상 매우 강함
    해독 예상 시간은 초당 100억 회를 시도하는 오프라인 GPU 공격을 가정한 값(2ᴱ ÷ 10¹⁰초)입니다.

    흔한 단어 감점에는 실제로 가장 많이 쓰이는 비밀번호 70개 목록을 사용합니다(password, qwerty, 한글 단어를 영타로 친 dkssud 등). 부분 문자열로 검사하므로 password1!처럼 뒤에 숫자·기호를 붙인 변형도 걸립니다. 이 목록은 유출 비밀번호 데이터베이스 전체가 아니므로, 감점이 없다고 해서 유출 목록에 없다는 뜻은 아닙니다.

    이 산식은 무작위 생성 비밀번호에 잘 맞는 추정치입니다. 사람이 직접 만든 비밀번호는 생일·이름 등 여기서 잡지 못하는 패턴이 있을 수 있어 실제 강도는 표시보다 낮을 수 있습니다. 자세한 기준은 안전한 비밀번호 만들기 가이드(NIST 기준)를 참고하세요.

    사용법

    1. 길이를 정합니다. 중요한 계정이라면 16자 이상을 권장합니다.
    2. 포함할 문자 종류와 제외 옵션을 선택합니다.
    3. 생성 버튼을 누르고, 마음에 드는 항목의 복사 버튼을 누릅니다.
    4. 클립보드 자동 지움을 켜두면 복사 후 설정한 시간이 지나 클립보드가 비워집니다(탭이 열려 있는 동안에만 동작).

    자주 묻는 질문

    생성된 비밀번호가 서버에 기록되나요?

    아니요. 생성은 전부 브라우저 안의 자바스크립트로 실행되고 네트워크 요청 자체가 없습니다. 새로고침하면 결과도 사라집니다.

    몇 자로 만드는 게 안전한가요?

    미국 NIST SP 800-63B는 길이를 가장 중요한 요소로 봅니다. 무작위 생성 기준으로 일반 계정은 12~16자, 금융·메인 이메일 등 중요 계정은 16자 이상 + 문자 종류 3가지 이상을 권장합니다.

    클립보드 자동 지움은 어떻게 동작하나요?

    복사 후 설정한 시간이 지나면 클립보드를 공백으로 덮어씁니다. 브라우저 보안 정책상 이 페이지 탭이 열려 있는 동안에만 동작하며, 탭을 닫으면 자동 지움도 함께 취소되니 중요한 경우 직접 다른 텍스트를 복사해 덮어쓰세요.

    강도 미터가 "강함"이면 무조건 안전한가요?

    강도는 무차별 대입 공격에 대한 수학적 추정일 뿐입니다. 같은 비밀번호를 여러 사이트에서 재사용하면 유출 시 함께 뚫리므로, 사이트마다 다른 비밀번호 + 비밀번호 관리자 + 2단계 인증을 함께 쓰는 것이 안전합니다.
